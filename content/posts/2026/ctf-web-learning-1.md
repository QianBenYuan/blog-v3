## CTF Web学习（1号）

### 一、网络基础协议

#### 1.HTTP/HTTPS 协议

- HTTP 全称：HyperText Transfer Protocol（超文本传输协议）
- HTTP：明文传输，数据裸奔，中间人可抓包查看内容，默认端口  80 
- HTTPS：HTTP + SSL/TLS加密，传输数据加密，抓包仅能看到密文，默认端口  443 
- HTTP协议作用：规定浏览器与Web服务器之间，请求、响应数据的统一通信规则

#### 2.SSL/TLS 加密

- 是一套网络加密协议，专门用于给HTTP数据加密，升级为HTTPS
- 通信前双方握手协商密钥，全程加密传输数据，防止数据被窃取、篡改
- SSL为老旧版本，目前全网通用TLS协议，日常统称SSL/TLS

#### 3.传输层协议（TCP）

- TCP是互联网核心传输协议，HTTP、Redis、MySQL、SSH均基于TCP
- 特性：三次握手建立连接、数据可靠传输、丢包重传、有序送达
- CTF用途：gopher协议可自定义TCP原始数据包，用于SSRF内网攻击

#### 4.Gopher协议基础

- Gopher 是老旧 TCP 文本传输协议，默认端口 70，诞生早于 HTTP
- 现已被淘汰民用网络，仅用于 CTF SSRF 高级利用
- 核心能力：可直接构造、发送任意原始 TCP 数据包，不受 HTTP 格式限制
- HTTP 只能发送规范网页请求；Gopher 可以向内网任意端口自定义发包

##### 4.1.GopherCTF 核心作用：

- 突破普通 SSRF 限制，攻击内网非 HTTP 服务
- 常用于攻击：Redis、MySQL、FastCGI 等内网服务
- 可实现写 Webshell、远程命令执行、内网探测等高危操作

##### 4.2.Gopher 固定规则：

- 标准格式： gopher://ip:port/_数据包 
- 斜杠后第一个字符会被自动丢弃，必须用下划线  _  占位
- 协议换行符  \r\n  必须 URL 编码为  %0d%0a 

### 二、网页前端三大件

#### 1.HTML（超文本标记语言）

- 网页骨架结构，负责定义页面所有元素（文字、按钮、图片、输入框）
- 仅为标记语言，==无法执行逻辑代码==，仅做页面展示结构
- 后缀 `.html `为==静态文件==，服务器直接原样返回给浏览器，不执行任何代码

#### 2.CSS（层叠样式表）

- 网页美化样式，负责控制页面颜色、字体、大小、布局、边距等外观效果
- 无业务逻辑，仅负责视觉渲染，纯前端展示技术

#### 3.JavaScript（JS）

- 网页交互脚本语言，运行在浏览器前端
- 功能：实现==点击弹窗==、表单校验、页面动态变化、数据获取等交互效果
- CTF关联：XSS漏洞本质是恶意JS代码在受害者浏览器执行

#### 4.超文本（HyperText）

- 区别于普通纯文本，超文本==可嵌入==链接、图片、视频
- 支持页面互相跳转，是HTTP、HTML的核心基础定义

### 三、静态页面 & 动态页面

#### 1.静态文件（index.html）

- 服务器==不执行代码==，直接将原文件返回浏览器
- 浏览器本地完成页面渲染，所有用户访问内容完全一致

#### 2.动态文件（index.php）

- PHP为服务端动态脚本语言，文件后缀  .php 
- 运行逻辑：服务器执行PHP代码 → 生成HTML内容 → 返回给浏览器渲染
- 不同用户、不同参数，可返回不同内容，属于动态网页

#### 3.脚本的定义

- 无需编译，通过==解释器==直接==运行的代码==
- 常见脚本：PHP、JS、Python、Bash，CTF中RCE、webshell均基于脚本执行

### 四、Web服务器

#### 1.网页服务器作用

- 软件：Nginx、Apache
- 核心功能：监听80/443端口，==接收==浏览器HTTP==请求==，==响应网页资源==
- 静态资源（html/图片）直接返回，`动态PHP`请求转发给`PHP-FPM`处理

#### 2.Nginx & Apache 区别

- Nginx：高并发、占用内存小、速度快，目前主流网站、CTF靶机首选，擅长`反向代理`、`负载均衡`
- Apache：老牌服务器，兼容性强，动态脚本适配好，但并发性能弱、资源占用高

#### 3.CGI & PHP-FPM

- CGI：`通用网关协议`，规定Web服务器如何对接PHP，性能差，老旧淘汰
- PHP-FPM：`PHP专用进程管理器`，常驻进程待命，快速处理PHP请求
- 工作流程：`Nginx/Apache接收PHP请求 → 转发给PHP-FPM执行代码 → 返回结果`

#### 4.服务器配置文件

##### 4.1.`.conf / .cnf`

- 均为`配置文件后缀`，纯文本格式，用于保存软件运行参数
-  .conf ：Nginx、Apache主流使用
-  .cnf ：MySQL主流使用
- 修改后需重启服务方可生效

##### 4.2.`apache2.conf`

- Apache全局主配置文件， 2 代表Apache2.x版本
- 控制整个服务器所有网站的全局规则、权限、模块
- 修改后必须重启Apache服务生效

##### 4.3.`.htaccess`

- Apache专属目录级配置文件，无需重启服务
- 仅对当前文件夹及子文件夹生效
- CTF核心用途：设置路由规则、文件解析规则、页面重定向、漏洞利用

#### 5.重定向

- 服务器告知浏览器资源地址变更，浏览器自动跳转新URL
- 分为301永久重定向、302临时重定向
- 可用于页面跳转、漏洞绕过、URL伪装

### 五、前后端基础区分

#### 1.前端

- 运行环境：用户浏览器
- 包含技术：HTML、CSS、JS
- 特点：代码公开可见，负责页面展示、收集用户输入

#### 2.后端

- 运行环境：服务器（用户不可见）
- 包含技术：PHP、Python、Java、数据库、服务器配置
- 特点：代码私密，负责处理逻辑、读写数据、执行命令、校验权限

#### 3.前后端关系

- 前端：收集用户操作、展示结果
- 后端：处理前端提交的数据，完成运算、查库、权限校验
- 所有漏洞（注入、SSRF、RCE）几乎均为后端逻辑漏洞

### 六、HTTP 完整请求体系

#### 1.什么是请求

客户端（浏览器/工具）向服务器发送一段规范数据包，索要资源、提交数据，这个行为叫「请求」。

#### 2.请求结构四要素

##### 2.1.路径 path：

服务器资源位置，如  `/index.php` 

##### 2.2.GET 参数：

URL  `?`  后的数据，属于链接一部分

##### 2.3.请求头 header：

附加信息

##### 2.4.请求体 body：

POST、上传、JSON 数据存放位置

#### 3.GET 参数:

- 放在 URL 问号后： `?id=1&name=admin` 
- 公开可见、长度有限
- CTF 核心漏洞点：GET 注入、XSS、越权

#### 4.POST 数据：

- 放在==请求体中==，不在 URL 显示
- 容量大、适合传密码、表单、大量数据
- 文件上传、php://input 读取均依赖 POST

#### 5.文件上传：

- 属于 POST 的特殊模式
- 需要特定编码格式  multipart/form-data 
- CTF 高频漏洞：文件上传漏洞传 webshell

### 七、抓包原理

#### 1.什么是抓包

拦截、查看、修改浏览器与服务器之间的 HTTP 数据包。

#### 2.抓包能干什么

- 修改 GET/POST 数据制造注入
- 修改请求头绕过限制
- 伪造身份、伪造 IP
- 查看隐藏参数、隐藏路径

#### 3.常用工具

Burp Suite、Fiddler

### 八、请求头

#### 1.Content-Type

告诉服务器「本次==请求体==是什么==格式==」
常见三种：

1.  x-www-form-urlencoded ：普通表单
2.  multipart/form-data ：文件上传专用
3.  application/json ：接口 JSON 数据

#### 2.User-Agent

标识客户端设备、浏览器信息。

- CTF 用途：后台只允许特定 UA、伪造 UA 绕过过滤。

#### 3.Referer

记录「你从哪个页面跳转过来」。

- 网站防盗链常用
- 可伪造绕过防盗链、白名单检测

#### 4.X-Forwarded-For（XFF）

反向代理专用头，代表真实用户 IP。

- 服务器信任此头 → 可伪造内网 IP  127.0.0.1  绕过后台 IP 限制

### 九、请求体编码格式

#### 1.编码格式作用

POST 数据必须声明格式，否则服务器无法解析数据。

#### 2.multipart/form-data

- 拆分多个数据块传输
- 唯一支持二进制、文件上传的格式

### 十、JSON 数据格式

- 定义：轻量级**结构化数据格式**，用于**接口传输数据**。
- 格式特征：键值对、大括号包裹、纯文本、程序极易解析

```
{"user":"admin","id":1}
```

- CTF 场景：接口注入、JSON 越权、JWT 解析

### 十一、XML数据格式

- 定义：可扩展标记语言，用于**传输、存储结构化数据**，类似 HTML。

- CTF 漏洞：
	- XXE 漏洞（XML外部实体注入）
	- 可读取服务器本地文件、探测内网

### 十二、日志记录

- 定义：服务器自动记录：访问 IP、访问路径、请求参数、报错信息、时间

- CTF 用途：从日志泄露中找源码路径、泄露 payload、泄露后台地址

### 十三、身份认证四大核心概念

#### 1.明文

- 指未加密、未处理、肉眼可直接读懂的原始文本。
- 例：密码  admin123  直接写在文件里就是明文。
- 网络安全原则：密码绝对不能明文存储。

#### 2.哈希（Hash）

- 单向加密算法：明文可以算出哈希，哈希无法反向算出明文。
- 相同明文、相同算法，永远得到相同哈希值。
- 作用：服务器只存哈希，不存明文密码，保证密码安全。

#### 3.密码哈希验证流程（登录原理）

##### 3.1用户输入明文密码

##### 3.2系统用相同哈希算法计算输入密码的哈希

##### 3.3和系统保存的哈希对比

##### 3.4一致则登录成功，不一致拒绝登录

#### 4./etc/shadow 文件

- Linux 系统专门存放用户密码哈希的系统文件。
- 不存明文，只存哈希字符串。
- 权限极高，普通用户无法读取。
- CTF用途：拿到 shadow 文件可爆破密码。

#### 5.哈希爆破工具

- John：老牌哈希爆破工具，简单易用。
- Hashcat：GPU加速，爆破速度极快，CTF主流工具。
- 原理：字典逐个跑，算哈希比对，匹配成功得到明文密码。

### 十四、Cookie 详解

#### 1.定义

- 浏览器自带的本地存储机制，是一块自动保存数据的空间。
- 由服务器下发，浏览器自动保存。

#### 2.特性

- 下次访问同网站，浏览器自动携带 Cookie。
- 用于维持用户登录状态、记录身份。
- Cookie 是「容器」，不是身份凭证。

### 十五、SessionID 会话机制

#### 1.定义

服务器端会话认证机制，传统网站默认登录方式。

#### 2.登录流程

1. 用户登录成功
2. 服务器生成唯一 SessionID，在服务器内存/数据库保存你的登录信息
3. 服务器下发指令，让浏览器把 SessionID 存入 Cookie
4. 后续所有请求，浏览器自动带 Cookie（携带 SessionID）
5. 服务器通过 SessionID 查询你的会话，识别你是谁

#### 3.区别

- Session数据存在==服务器==
- SessionID存在==浏览器==Cookie
- Cookie=盒子，SessionID=卡号，Session数据=你的个人信息

### 十六、Token 鉴权机制

#### 1.什么是 Token 鉴权

新式身份认证方式，无需服务器保存会话。

#### 2.原理

1. 登录成功，服务器生成一段带签名的凭证字符串（Token）
2. Token 自带用户信息
3. 客户端保存 Token（Cookie / 请求头）
4. 每次请求带 Token
5. 服务器只校验签名，不用查数据库

#### 3.优缺点

- 优点：减轻服务器压力、适合分布式、多服务器集群
- 缺点：一旦签发，过期前无法主动销毁

### 十七、JWT（最常用 Token 格式）

#### 1.定义

JSON Web Token，目前互联网最主流 Token 标准。

#### 2.三段结构

 `header.payload.signature` 

1. header：算法、类型（Base64编码）
2. payload：用户ID、权限、信息（可解码查看，不是加密）
3. signature：加密签名（防篡改核心）

#### 3.在CTF的作用 

- payload 可直接解码看信息
- 弱密钥可伪造 JWT，直接冒充管理员

### 十八、三者终极关系（Cookie / SessionID / Token）

#### 1.简单总结

1. Cookie：存储工具（容器），浏览器功能
2. SessionID：传统登录凭证，编号存在Cookie，数据在服务端
3. Token/JWT：新式登录凭证，自带数据，靠签名校验

#### 2.区分

- Session：服务端存数据，客户端存编号
- JWT Token：客户端存全部信息+签名，服务端不存数据
- Cookie：用来装 SessionID 或 Token 的浏览器==容器==

### 十九、数据库基础

#### 1.数据库作用

数据库是有组织存放数据的软件，用于快速实现数据的增加、删除、查询、修改。网站账号、文章、业务数据都保存在数据库中。

#### 2.MySQL（磁盘型数据库）

- 数据主要存储在硬盘上。
- 优点：持久保存数据，关机数据不会丢失。
- 缺点：读写速度相对内存数据库慢。
- CTF考点：SQL注入，读取、修改库内数据。

#### 3.Redis（内存型键值数据库）

- 核心：运行时数据优先放在服务器内存条（RAM）。
- 特点：读写速度极快；断电内存数据丢失，支持RDB/AOF机制定期备份到硬盘做持久化。
- 常用场景：缓存、临时会话、计数器。
- CTF考点：SSRF攻击Redis，写入webshell、定时任务获取服务器权限。

### 二十、接口 API

#### 1.API（接口程序）定义

API是后端提供的数据接口程序，不渲染网页页面，只返回结构化数据（一般为JSON），供前端、其他程序调用。

#### 2.示例

访问  `/api/getuser?id=1` ，后端返回  `{"name":"test","id":1}` ，只有数据，没有页面UI。

#### 3.AI付费API（豆包、DeepSeek）

属于API的一类。客户端发送文本请求，服务商后端调用大模型运算，返回AI回答。调用时携带Token鉴权，服务商统计token用量计费。

### 二十一、反向代理 & 负载均衡 & 路由 & 访问控制

#### 1.反向代理

反向代理部署在业务服务器前端。用户访问代理服务器，由代理代替用户向后端真实服务器请求资源，再将结果返回用户。用户无法获知后端真实IP。常用软件：Nginx。

#### 2.路由

根据访问的URL路径分发请求。例如访问  `/admin`  转发后台页面； `/api`  交给接口程序。

#### 3.负载均衡

多台相同后端服务器集群，反向代理将用户请求分发到不同机器，分摊压力，防止单台服务器过载。分发策略常用轮询。

#### 4.访问控制

配置规则限制资源访问权限。例如仅内网IP可访问后台、登录后才可访问页面、IP黑名单拦截。CTF考点：伪造XFF请求头绕过IP限制。

### 二十二、SSRF（服务端请求伪造）

#### 1.定义

服务器代替客户端发起网络请求，不是浏览器发起请求。

#### 2.原理

后端代码会访问用户可控的URL，攻击者传入恶意地址，迫使服务器访问本地、内网服务。

#### 3.在CTF的作用

- 探测内网端口、访问内网服务
- 使用gopher协议构造TCP数据包，攻击Redis等内网服务

### 二十三、注入漏洞总述

#### 1.注入的核心原理

程序原本只把用户输入当作普通字符串；攻击者构造特殊输入，破坏原有语句结构，让后端把输入当作代码/命令执行，这类漏洞统称为注入。

#### 2.SQL注入

用户可控输入直接拼接进SQL语句，篡改SQL逻辑，查询/修改数据库数据。
GET参数注入：GET参数 `?id=xxx` 可控，参数直接拼入SQL，传入payload触发注入。
示例payload： `1' or '1'='1-- -` 

#### 3.XXE（XML外部实体注入）

后端解析XML时开启外部实体，攻击者构造恶意XML，读取服务器本地文件、探测内网。

### 二十四、XSS 跨站脚本

#### 1.定义

Cross Site Scripting，跨站脚本漏洞。攻击者注入JS代码，页面未做过滤，代码在受害者浏览器中执行。

#### 2.XSS 和 JS 的关系与区别

- JS是编程语言；XSS是漏洞攻击方式，利用JS实现攻击效果。
- JS本身无害；如果网站没有过滤用户输入，恶意JS被页面渲染执行，就形成XSS。

#### 3.XSS三类

1. 存储型XSS：攻击代码存入==数据库==，所有人访问页面都会触发，危害最大，适合挂恶意脚本、批量偷Cookie。

2. 反射型XSS：需要诱骗用户携带payload访问==链接==，一次性触发。payload放在URL参数，不存入服务器。

3. DOM型XSS：==纯前端JS漏洞==，数据不经过后端存储，只靠前端JS解析用户输入。

	限制：XSS只能作用访问页面的用户浏览器，不能直接拿下服务器权限。

#### 4.CTF攻击效果

盗取Cookie、劫持==前端==页面、诱导操作。

### 二十五、Git 版本控制

#### 1.Git 定义

分布式版本控制工具，用于管理代码，记录每一次修改，支持回退旧版本、多人协同开发。

#### 2.分布式版本控制工具含义

每一台本地电脑都会保存完整代码仓库和全部历史记录，不依赖单一中心服务器，可以离线提交代码。联网后再同步版本。
对比集中式SVN：只有中央服务器保存完整代码，本地只有当前代码，断网无法提交。

#### 3.CTF考点：.git源码泄露

网站目录暴露 `.git` 文件夹，攻击者可以下载完整源码，寻找漏洞。

### 二十六、包管理器与Node相关工具

#### 1.包管理器定义

自动下载、安装、升级、卸载别人写好的代码库（依赖库）的工具，无需手动下载源码。

- Node：npm / yarn / pnpm
- Python：pip
- PHP：composer

#### 2.项目依赖库

第三方已经编写完成的代码库，项目直接引入使用，不用从零开发。项目在 `package.json` 记录依赖清单。

#### 3.npm / yarn / pnpm

- npm：Node自带，老牌工具，旧版本安装慢、占用磁盘大。
- yarn：早期为修复npm缺陷开发，现在使用量下降。
- pnpm：新一代，安装速度最快，磁盘占用最小，采用硬链接复用包。三者功能基本一致，命令略有差异。

#### 4.Bash、Node.js、node

- Bash：Linux默认终端shell（命令解释器），终端输入命令交给bash执行，CTF中RCE经常执行bash命令。
- Node.js：服务端JS运行环境，可以用JS编写后端程序。
- node：终端调用Node.js的命令。

### 二十七、CTF基础攻击名词

#### 1.Payload

攻击载荷，指触发漏洞的攻击语句、代码。例如SQL注入的 `1' or '1'='1-- -` 就是payload。

#### 2.Webshell

上传到服务器的一句话后门脚本，拿到webshell即可在服务器执行系统命令，控制网站。常见 shell.php 。

#### 3.RCE（远程代码执行）

远程控制服务器执行系统命令，属于高危漏洞。

### 二十八、路径与Payload查找

#### 1.寻找路径的方法

- 目录扫描工具dirsearch、dirb扫描后台路径
- 源码泄露、robots.txt、页面注释、报错信息、日志中发现路径
- 常见猜测路径： `/admin` 、 `/backup` 、 `/.git` 

#### 2.使用Payload

找到可控输入点（GET参数、POST表单），填入payload发送请求触发漏洞

### 二十九、CTF 靶机环境相关基础概念

#### 1.网站根目录

- 定义：Web服务器==对外暴露==的文件夹，浏览器访问网站时，服务器会从这个目录寻找网页文件。
- 示例：Apache默认根目录  `/var/www/html` ；Nginx常见根目录  `/usr/share/nginx/html` 。
- 特点：只有根目录内的文件，才能通过HTTP访问；根目录以外的文件，正常情况下无法直接访问。

#### 2.持久化目录

- 定义：数据写入后，重启服务器、重启程序，数据依然保留的目录，数据保存在磁盘。
- 对比：内存里的数据重启丢失；持久化目录数据保存在硬盘。
- 注意：持久化目录不会自动变成网站根目录，需要手动修改Web服务配置，将该目录设置为网站根目录才可以通过网页访问。

#### 3.网站根目录与持久化目录区别

1. 网站根目录：访问权限概念，控制哪些文件能通过web请求读取/上传。
2. 持久化目录：数据存储特性概念，代表数据断电不消失。

- 两者可以是同一个文件夹，也可以互相独立。

### 三十、文件上传与 Webshell 原理

#### 1.Webshell 

放置在网站根目录的后门脚本，访问该文件就可以执行服务器命令。
常见  `shell.php` 。

#### 2.shell.php 如何拿到webshell

1. 攻击者利用文件上传漏洞，绕过后端的文件后缀、MIME类型校验。
2. 将shell.php上传到网站根目录。
3. 在浏览器直接访问  `http://xxx/shell.php` ，执行脚本，获得服务器命令执行能力。

限制：如果上传到网站根目录之外，无法通过web访问，webshell失效。

### 三十一、CGI / FPM 

#### 1.CGI

通用网关接口，定义Web服务器如何把请求交给后端脚本程序处理。老旧方案，性能差，现在很少使用。

#### 2.PHP-FPM

PHP的进程管理程序，常驻内存。
流程：Web服务器（Apache/Nginx）收到 `.php` 请求 → 转发请求交给PHP-FPM → FPM执行PHP代码，将执行结果返回Web服务器，再返回浏览器。

### 三十二、短链接

#### 1.短链接原理

将很长的URL压缩为简短地址，访问短地址，服务器返回302重定向跳转到原始长URL。

#### 2.CTF场景

用于隐藏真实URL，SSRF场景经常使用短链接做payload中转。

### 三十三、CTF常用工具

#### 1.目录扫描工具

- dirsearch、dirb：自动批量请求常见路径，扫描网站隐藏后台、备份文件、.git目录。

#### 2.抓包工具

- Burp Suite：CTF Web最主流抓包改包工具，可修改请求头、GET/POST参数，发送自定义payload。
- Fiddler：Windows平台简易抓包工具。

#### 3.哈希爆破工具

- John、Hashcat：读取哈希字符串，使用密码字典爆破，尝试还原明文密码。

### 三十四、一些其他内容

#### 1.静态与动态区分

- html：静态，服务器直接返回文件，==不执行代码==
- php：动态，服务器==执行代码==，返回执行后的结果

#### 2.注入类漏洞通用记忆点

注入本质：用户输入被当成代码执行。
SQL注入、XXE、命令注入都属于这一类。

#### 3.Cooike/Session/JWT Token

Cookie是容器；SessionID服务端存数据；JWT Token自带数据依靠签名校验。

#### 4.SSRF是什么

服务器发起请求，不是浏览器，用来访问内网、本地服务。

### 三十五、什么是XX？

#### 1.明文

未经加密、哈希处理，可以直接阅读的原始文本。密码不允许明文存储。

#### 2.脚本

无需编译，由解释器直接运行的代码，PHP、JS、Bash都属于脚本。

#### 3.HyperText（超文本）

可以包含链接、图片、多媒体的文本，是HTTP名字来源。

### 三十六、Web 注入类漏洞共性

核心：外部可控输入，没有做过滤/转义，直接拼入后端语句，输入被解释成代码执行。

- SQL注入：拼入SQL查询语句，读写数据库
- 命令注入：拼入系统shell命令，直接执行操作系统指令（高危，可拿服务器权限）
- XXE注入：解析XML触发，读取本地文件、探测内网

简单来说就是：输入没被过滤，当成代码跑，就是注入

### 三十七、文件相关漏洞

#### 1.文件上传漏洞

原理：后端未严格校验上传文件后缀、文件内容，允许上传脚本文件。
利用流程：上传webshell脚本 → 文件落至网站根目录 → 浏览器访问该脚本，实现RCE。
常见绕过思路：改后缀、修改Content-Type、图片马配合文件解析漏洞、.htaccess解析。

#### 2.文件包含漏洞

分为本地文件包含LFI、远程文件包含RFI。
原理：后端代码直接拼接用户传入的文件路径，读取文件内容。

- LFI（本地文件包含）：读取服务器本地任意文件，例如  `/etc/passwd` 、 `/etc/shadow` 
- RFI（远程文件包含）：包含远程服务器上的文件，执行远程代码（现在PHP默认关闭）
CTF技巧：结合日志包含、session包含，把代码写入文件再包含执行，拿到RCE。

#### 3.目录遍历（路径穿越）

Payload示例： `../` ，利用 `../` 向上跳转目录，突破固定目录限制，读取服务器任意文件。
例： `?file=../etc/passwd` 

### 三十八、CSRF 跨站请求伪造

#### 1.定义

跨站请求伪造，诱导已登录用户在不知情的情况下，发起非自愿请求。

#### 2.原理

用户登录A网站，Cookie保存在浏览器；访问恶意页面，恶意页面自动发起请求访问A网站。浏览器自动带上Cookie，服务器认为是用户本人操作。

#### 3.特点

- 无法获取Cookie内容，直接利用浏览器自动携带Cookie的特性
- 防御手段：Token校验、验证Referer

### 三十九、PHP 语言安全

#### 1.PHP CLI模式

PHP命令行模式，在服务器终端直接执行PHP代码，不依赖Web服务器、不经过浏览器。
命令示例：

```
php -r "echo system('id');"
```


区分：网页模式（CGI/FPM）是接收HTTP请求执行PHP；CLI是终端直接运行。

#### 2.PHP 伪协议

CTF文件包含最常用

-  `php://input` ：读取POST请求体中的数据
-  `php://filter` ：读取文件并编码输出，常用来读取源码
示例payload： `?file=php://filter/read=convert.base64-encode/resource=index.php` 

#### 3.危险函数

触发RCE的PHP函数，若用户可控参数传入这类函数，会产生命令注入漏洞
 `system()` 、 `exec()` 、 `shell_exec()` 、 `passthru()` 

### 四十、CTF 靶机常见系统文件

#### 1./etc/passwd

存储用户账号基本信息，不存密码哈希，普通用户可读，可以拿到系统所有用户名。

#### 2./etc/shadow

存储用户密码哈希，权限严格，仅root可读，拿到后可用john/hashcat爆破密码。

#### 3./etc/apache2/apache2.conf

Apache2主配置文件，控制全局Web服务设置。后缀数字2代表Apache2版本。

### 四十一、Payload 的分类

#### 1.SQL注入Payload

 `1' or '1'='1-- -` 

#### 2.目录穿越Payload

 `../` 、 `../../` 

#### 3.文件包含Payload

 `php://filter/read=convert.base64-encode/resource=index.php` 

#### 4.XSS Payload

 <script>alert(1)</script> 

### 四十二、Web 防御

#### 1.WAF 网站应用防火墙

部署在Web前端，识别并拦截恶意payload（注入、XSS等攻击）。CTF大量考点：WAF绕过。

#### 2.输入过滤、转义

后端对特殊符号 `' " < > &` 转义，阻止注入、XSS。

#### 3.验证码、CSRF Token

防止CSRF、批量爆破。

#### 4.最小权限原则

网站运行账号权限尽量低，就算被上传webshell，也很难拿到服务器最高root权限。
