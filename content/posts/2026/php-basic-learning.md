### 一.搭建环境——PHP简介

#### 1.基础概念

PHP 全称超文本预处理器（Hypertext Preprocessor），属于==后端脚本编程语言==，多用于==搭建网页服务==，也是 CTF Web 考题里最常见的后端语言。
用户在浏览器访问网页时，前端页面负责展示界面，==PHP 作为服务端程序接收传入的数据==，再对接 MySQL、MariaDB 这类数据库调取、写入数据，最后拼装成网页内容返回浏览器呈现出来。

#### 2.核心作用

1. 搭建个人博客、论坛、小型官网等网页站点；
2. 实现账号注册、登录、内容查询这类功能，本质是 PHP 程序操作数据库；
3. 搭配 Nginx、Apache、MySQL 即可快速搭建站点，部署门槛低，所以绝大多数新手漏洞靶场，都采用 PHP+数据库的组合。

#### 3.和其他编程语言区分

1. C/C++：偏向电脑==底层==程序、桌面软件开发；
2. Python：多用于爬虫、数据分析、==后端开发==、工具脚本；
3. Java：偏向大型==商用项目后端==；
4. PHP 定位专一，主打==网页后端开发==，上手简单，历史版本漏洞繁多，因此成为 Web 漏洞练习的主流载体。

#### 4.结合SQL注入的原理

网站登录功能的简易PHP逻辑示例：

```php
// 获取用户输入账号密码
$username = $_GET['username'];
$password = $_GET['password'];
// 直接拼接参数组合SQL语句
$sql = "select * from user where username='$username' and password='$pwd'";
```

程序没有对用户输入做==过滤处理==，直接把参数拼接进SQL语句。此时传入闭合符号与 union select 这类注入载荷，就==能篡改原本的查询语句==，读取数据库内隐藏数据，这也是PHP靶场高频出现SQL注入漏洞的缘由。

#### 5.优缺点

**优点**

环境搭建简便，代码可读性高，适配网页学习、漏洞实操练习。

**缺点**

老旧PHP版本存在大量原生漏洞，若开发者没有做好输入过滤、参数预处理，极易产生注入、文件包含等安全漏洞。

#### 静态网页 vs 动态网页

**静态网页：内容写死，所有人看的都一样；动态网页：数据实时调取，不同人看不一样。**

#### 6.静态网页特点

后缀一般是 `.html`、`.htm`

##### (1)内容写死在文件里

程序员提前把文字、图片全部写进网页文件。你打开网页，服务器直接把这个完整文件发给你的浏览器，浏览器直接渲染显示。

##### (2)**没有数据库**，不读取后台数据

##### (3)所有人访问看到的内容完全相同，不会因人而异

##### (4)交互很差：

只能看，不能提交数据。不能登录、不能评论、不能点赞，你没法往网页里存东西。

##### (5)**打开速度快**，服务器压力小；

修改内容必须改源代码文件，改完重新上传服务器。

如：早期简单个人介绍页、说明书页面，只有文字图片，不能登录留言。

#### 7.动态网页特点

后缀常见 `.php`、`.jsp`、`.asp`，==现在大多前后端分离==，后缀还是 html，但本质是动态。

##### (1)网页不是提前写完整的，服务器收到你的访问请求后，==临时拼接生成网页==，会去读取数据库的数据，再把组装好的页面发给浏览器。

##### (2)搭配数据库（存账号、评论、商品信息）

不同人看到内容可以不一样

登录你的账号，看到你的订单；别人登录看到别人的订单。

##### (3)可以交互：登录、注册、发评论、购物下单、搜索，数据会保存到后台。

##### (4)速度比静态慢一点，服务器压力更大；修改内容不用改代码，直接改数据库里的数据就行。

如：淘宝、抖音网页版、B 站、朋友圈网页、考试登录系统。

#### 静态网站与动态网站的区别

| 对比项       | 静态网页                 | 动态网页                                 |
| ------------ | ------------------------ | ---------------------------------------- |
| 内容来源     | 读取预先写好的 html 文件 | 服务器运行程序，读取数据库，临时生成页面 |
| 数据库       | 不使用                   | 使用数据库                               |
| 用户看到内容 | 全部一模一样             | 可以因人而异                             |
| 用户交互     | 只能浏览，无法提交数据   | 支持登录、评论、搜索、下单等操作         |
| 修改内容方式 | 修改源代码文件           | 修改数据库数据，无需改动网页代码         |
| 访问速度     | 快                       | 相对较慢                                 |
| 典型后缀     | `.html` `.htm`           | `.php` `.jsp`（现代项目后缀不绝对）      |

### 二.搭建环境——网站基本概念

#### 1.服务器

- 服务器是==提供计算服务的设备==。能不能当服务器，不靠硬件，看你装了什么服务软件。

- 服务器本质就是一台电脑。普通电脑用来刷视频、打游戏。

- 服务器专门用来==对外提供服务==，比如跑网站、存文件、跑数据库。硬件上和普通电脑部件差不多，都有 CPU、内存、硬盘。但是==服务器追求长时间稳定不关机、高可靠、安全性强==。任何电脑都可以变成服务器，只要装上对应的服务软件。

- 装 Apache/Tomcat/IIS → 变成 Web 服务器，用来跑网站

- 装数据库软件 → 数据库服务器

- 装文件服务软件 → 文件服务器

  如：Tomcat、Apache、IIS，这三个就是 Web 服务软件，装上之后你的机器就可以对外提供网站访问。

#### 2.IP 与 IP 地址

- IP 是互联网通信的一套规则，IP 地址是机器的编号，全球唯一。
- 把互联网想象成快递网络。IP 协议：就是大家约定好的一套快递运输规则，所有联网设备都遵守这套规则，互相才能说话通信。
- IP 地址：就是每一台联网设备的门牌号码，每一台设备编号不一样，具有唯一性。没有门牌（IP），数据就不知道该发给哪一台电脑。
- 举例：192.168.1.100 就是 IP 地址。

#### 3.域名

域名 = IP 的 "好记外号"
IP 是一串数字，人很难记住。域名就是给 IP 起的好记的名字，相当于门牌的别名。比如 baidu.com 就是域名。一台服务器有一串数字 IP，我们不用记枯燥数字，直接输入域名就可以访问。一个 IP 可以绑定好多个不同域名；一个域名只能指向一个 IP。

#### 4. DNS（域名系统）

做==域名 ↔ IP== 的翻译工作，这个翻译过程叫==域名解析==
DNS 相当于互联网的电话号码本 / 翻译官。人输入域名 baidu.com（人看得懂），机器只能识别 IP 数字。DNS 负责查表格，把域名翻译成对应的 IP 地址。把域名翻译成 IP 的这一步操作，就叫域名解析。
流程：
你浏览器输入 baidu.com → 去找 DNS 服务器 → DNS 查出对应的 IP → 浏览器拿着 IP 去找服务器。

#### 5.端口 Port

分两种：物理端口（实物接口）、虚拟端口（网络安全、CTF 重点是虚拟端口）

- 物理端口:

  看得见摸得到，电脑主机上面的网口、USB 口。比如网线插的 RJ45 网口。

- 虚拟端口:

  软件逻辑端口，看不见。

  端口就是用来区分同一台机器上不同服务的编号（0‑65535 数字）。

#### 6.常见默认端口：

- 80：普通网页 http 服务
- 443：加密网页 https
- 21：文件传输 FTP
- 22：远程连接 ssh

举例子：
同一台机器 IP：123.45.67.89
访问网站：走 80 端口
传文件：走 21 端口
IP 负责找到是哪一台机器；端口负责找到这台机器上面的哪一个软件服务。

#### 7.整套流程

- DNS 做域名解析，把域名翻译成服务器 IP；
- 通过 IP 找到互联网上那台服务器；
- 通过端口号，找到服务器上面对应的服务程序（比如 Web 网站服务）；
- 建立连接，网页内容返回给你的浏览器。

### 三.搭建环境——静态网站访问流程

![image-20260810222532067](/assets/php-basic/image-20260810222532067.png)

#### 1.核心名词

##### （1)**URL（统一资源定位）**：互联网上的==绝对路径==，示例：`http://localhost:80/index.html`

##### （2）**URI（统一资源标识）**：目标服务器机器上的==相对文件路径==，示例：`/index.html`

##### （3）**DNS 服务器**：把域名翻译成 IP 地址，分为两层本地 DNS：

- hosts 文件，本机优先查询
- 网络 DNS：网络上的域名解析服务

##### （4）**localhost**：本机域名，对应 IP `127.0.0.1`（回环地址，只访问自己本机）

##### （5）**端口**：用来定位服务器上的软件，Apache 网页服务默认 80 端口

#### 2. 完整访问步骤

##### （1）浏览器输入 URL：`http://localhost:80/index.html`

##### （2）浏览器发起 DNS 解析：

- 先查本机 hosts 本地 DNS，得到`localhost`对应 IP：`127.0.0.1`

- 本地没有才会去查询网络 DNS

##### （3）拿到 IP + 端口`127.0.0.1:80`，找到服务器，把 URI`/index.html`发给 Apache

##### （4）Apache 网页服务软件接收请求，根据 URI 去网页文件夹读取`index.html`文件内容

##### （5）Apache 把文件结果返回给浏览器

##### （6）浏览器解析收到的内容，展示网页

#### 3. 关键理解

##### （1）`127.0.0.1`就是访问**自己这台电脑**，不需要外网，本机就可以完成整套网页访问。

##### （2）hosts 文件优先级高于网络 DNS，可以手动修改域名对应的 IP。

##### （3）IP 负责找哪一台电脑，**端口负责找电脑上哪一个服务软件（Apache）**，URI 找软件内部的哪个文件。

##### （4）Apache 属于 Web 服务器软件，电脑安装它，普通电脑就变成网页服务器。

### 四.搭建环境——动态网站访问流程

![image-20260810224916969](/assets/php-basic/image-20260810224916969.png)

#### 1.完整访问步骤

##### （1）浏览器输入 URL：http://localhost:80/index.php

##### （2）DNS 解析：localhost解析回环 IP127.0.0.1

##### （3）浏览器通过 IP+80 端口，把请求发给 Apache，携带 URI /index.php

##### （4）Apache 识别到这是 php 文件，不直接把 php 代码丢回浏览器，交给 PHP 引擎处理

##### （5）PHP 引擎读取index.php源代码；如果代码有需求，去和数据库服务器交互，查询 / 修改数据

##### （6）PHP 引擎执行完毕，把 PHP 代码翻译成普通 HTML 代码，交还给 Apache

##### （7）Apache 把最终生成的 HTML 返回浏览器

##### （8）浏览器接收 HTML，解析渲染，展示网页

#### 2.静态 html 和动态 php 核心区别

| 类型           | 静态（index.html）                          | 动态（index.php）                                      |
| -------------- | ------------------------------------------- | ------------------------------------------------------ |
| 处理方式       | Apache 直接读取文件，原样把 html 返回浏览器 | Apache 交给 PHP 引擎执行代码，可操作数据库，输出 HTML  |
| 数据库         | 不能操作数据库                              | 可以读写数据库，页面内容可以变化                       |
| 浏览器拿到什么 | 原始 html 文件内容                          | PHP 运行之后生成的 html，**浏览器看不到原始 PHP 代码** |

Define SRVROOT "C:/Apache24"

```
cd C:\Apache24\bin
```

##### (3)执行语法校验

```
httpd.exe -t
```

输出 `Syntax OK` = 配置文件语法正常，可以继续；

  C:\Apache24\conf\original

  ```

  ```

#### 3.启动 Apache 服务

##### 方式 1：前台临时启动（学习调试用）

管理员 CMD，在`C:\Apache24\bin>`下执行

```
httpd.exe
```

> ⚠️运行后黑色命令窗口**不能关闭，最小化即可，关闭服务器立刻停止**
>
> 弹出 Windows 防火墙弹窗 → 点击【允许访问】，只勾选【专用网络】，公用网络不要勾选。

打开浏览器，地址栏输入访问测试：

```
http://127.0.0.1
```

页面显示 `It works!`，代表 Apache 搭建成功。

![image-20260811162511113](/assets/php-basic/image-20260811162511113.png)

##### 方式 2：安装 Windows 系统服务（开机自动启动，可选）

新开管理员 CMD，进入 bin 目录执行：

```
httpd.exe -k install
```

安装完成后，Apache 会随系统开机自动运行，不需要每次手动敲命令。

```

示例：放入

```
test.html
```

，浏览器访问：

```
http://127.0.0.1/test.html

| conf     | 服务核心配置目录，`httpd.conf` 主配置文件存放于此；`original`子目录保留原厂原始配置，配置出错时可从中复制文件恢复。 | 仅编辑`httpd.conf`，==建议使用系统记事本编辑==，避免编码异常 |

| logs     | 日志目录，记录访问记录、程序报错信息，排查服务异常可查阅此处日志文件。 | 一般不修改，出现故障时查看日志内容                           |

| icons    | 系统内置图标资源文件。                                       | 无需操作                                                     |
| include  | 存放拆分出来的附属配置片段。                                 | 无需操作                                                     |

### 六.安装Apache之httpd.exe介绍

####  1.启动服务

`httpd.exe` 就是 Apache 的服务程序，只有把这个程序跑起来，服务器才可以对外提供网页访问服务。

#### 2、验证功能（执行命令的注意点）

直接在 cmd 随便输入 `httpd.exe` 会提示不是内部命令，会报错。 原因：没有配置系统环境变量，系统找不到这个程序在哪。

解决办法： 先要切换到程序所在 bin 目录再执行命令。

```
cd C:\Apache24\bin
httpd.exe
```

#### 3、查看加载模块命令：

```
httpd.exe -M
```

作用：查看当前 Apache 已经加载了哪些功能模块。

模块分两类：

##### (1)静态模块：

服务器程序编译的时候直接打包进去，Apache一启动就直接加载，运行速度快。

##### (2) 动态模块：

存放在 modules 文件夹，需要在 httpd.conf 配置文件写配置才会加载，需要什么再开启什么，相对灵活。主要用来排查：需要用到的功能模块有没有成功加载。

#### 4、测试配置文件（非常重要） 命令：

```
httpd.exe -t
```

作用：检查 `conf/httpd.conf` 配置文件语法是否写错。

- 返回 `Syntax OK`：配置没有语法错误，可以正常启动服务；出现警告信息一般不影响运行。
- 返回报错信息：说明配置有地方写错，此时不要直接启动服务，根据报错提示回去修改配置文件，改完再检测。

### 七.配置默认站点

配置默认站点一共三件核心事情：

1. 指定网站根目录（网页存放的文件夹位置）
2. 设置 ServerName 主机别名，给站点起访问名字
3. 修改本地hosts文件，做本地域名解析，用名字代替IP访问

#### 1.确定网站根目录 DocumentRoot

##### (1)配置文件位置：

`conf/httpd.conf`

##### (2)指令：

`DocumentRoot`

作用：告诉Apache，浏览器访问的时候，去电脑哪个文件夹读取网页文件。

示例：

```
apache DocumentRoot "C:/Apache24/htdocs"
```

- 双引号里面就是网站根目录路径，**斜杠用 `/`，不要写Windows反斜杠 `\`**

- 当前使用默认路径 `C:/Apache24/htdocs`，不需要改动；以后想把网页放到别的文件夹，就修改这里路径。

  注意：路径不要带中文、空格，容易出现权限、访问报错。

#### 2、设置 ServerName 主机别名

- `Listen` 在 httpd.conf 里面统一配置监听端口（默认 80 端口）。
- `ServerName`：设置站点的主机名，只写主机名，**不要带上端口号**，端口交给 Listen 管理。
- 作用：定义这个网站对外识别的名字，例如 `localhost`。

> 部分版本配置放在 `conf.d/welcome.conf`，去掉行前面的`#`注释符号才会生效。

简单理解：

- DocumentRoot = 告诉==服务器网页==放在哪个==文件夹==
- ServerName = 告诉==服务器==这个==网站叫什么名字==

#### 3、修改配置后固定操作

##### (1)修改完任何配置文件，执行语法检测

```
httpd.exe -t
```

看到 `Syntax OK`，代表配置语法没问题；有警告一般不影响运行，报错就回去修改配置。

##### (2)检测通过之后，重启 Apache 服务，新配置才会加载生效。

实操习惯：**改完配置，先检测，再重启，不要直接访问页面。**

#### 4、本地 hosts 解析（本地 DNS）

hosts 文件路径：

```
C:\Windows\System32\drivers\etc\hosts
```

作用：本地域名解析，不依赖互联网 DNS，本机直接把域名翻译成 IP 地址。

添加一条记录：

```
127.0.0.1       localhost
```

含义：本机访问 `localhost` 的时候，电脑自动解析成 `127.0.0.1`。

注意：

- hosts 文件需要**管理员权限记事本打开**，普通权限无法保存修改。
- 格式：IP 地址 + 空格 + 域名，`#`开头的行属于注释，不会生效。

#### 5、浏览器访问验证

##### (1)浏览器输入：`http://localhost`

页面出现 `It works!`，代表整套默认站点配置成功。

##### (2)验证小技巧：

修改 htdocs 里面默认首页内容，刷新浏览器，页面跟着变化，就确认访问的就是 DocumentRoot 指定的文件夹。

#### 6.完整实操流程

##### (1)在 httpd.conf 确认 `DocumentRoot`，指定网页存放目录

##### (2)启用 `ServerName` 设置站点主机名

##### (3)修改 hosts 文件，完成 IP 与域名映射

##### (4)`httpd.exe -t` 校验配置语法

##### (5)重启 Apache 服务

##### (6)浏览器访问域名测试效果

#### 7.易踩坑

##### (1)DocumentRoot 路径斜杠要写 `/`，不能使用 Windows 的 `\`。

##### (2)ServerName 不要额外写端口，端口统一交给 Listen 指令。

##### (3)hosts 文件没有管理员权限，修改之后保存失败。

##### (4)修改配置忘记执行 `-t`检测，直接启动，造成服务启动失败。

##### (5)文件夹路径包含中文、空格，出现 403 禁止访问错误。
